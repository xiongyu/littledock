# 系统优化插件 0.1

小站 官方内置的独立插件，适用于运行后端的本机 Windows 11 x64；0.1.1 插件需要 小站 0.1.2 或以上，声明独占 Worker，使用异步宿主接口获取解锁状态和资源租约。随工作台提供，首次启动自动出现，也可禁用或卸载。入口、工作区、可选设置与字体全部通过公共 SDK 注册，不修改宿主导航或增加专用服务白名单。

## 当前首版

- 概览、开机启动、系统设置、空间管理、应用和恢复记录；彩色标题栏与卡片正文分层，跟随宿主浅深主题，支持窄屏。
- 读取 Run/RunOnce、启动文件夹、当前用户可见的开机/登录任务和自动服务。只允许停用当前用户 64 位视图的普通 Run 登记；小站 自身入口保留给托盘管理。登记不等于已启用，启动影响、StartupApproved、数字签名不推测。
- 10 项用户级文件管理、视觉及推荐提示设置。选择后预览原值/目标值，原值用 Windows 当前用户 DPAPI 加密，执行后读回；冲突或结果未知停止后续项。恢复前检查当前值，没有覆盖其他修改的强制按钮。
- 读取桌面与当前用户商店应用，提供 Windows 应用卸载入口；不执行任意卸载命令。
- 空间管理打开 Windows 存储设置。此版本不直接删除文件、清空回收站或搬动启动文件夹；这些动作仍在独立产品方案中，尚未开放。

不提供“健康分”、性能提升百分比、自动优化、注册表垃圾扫描、禁用安全功能或管理员提权。安装及启用不会自动扫描、修改系统或添加自启。系统设置效果可能需重新登录后查看，插件不会替用户重启。

## 安装与构建

正常使用无需另装：更新源码后重新启动 小站，在“插件中心 → 已安装”找到“系统优化（官方 · 内置）”，或直接点击左侧“系统优化”。点击“扫描本机”只读查询；选择项目并确认应用才会修改系统。真实写入尚未实机验收，应在测试 Windows 环境验证。

卸载后不会在重启或宿主更新时自动装回；从“插件中心 → 发现插件”点击“恢复安装”即可恢复。框架保留配置和数据，无需访问网络。本目录也保持可独立发布的结构，`runtime/`、`ui/main.js`、`windows/`、清单及图标须一并提供。

本仓库开发时运行：

```powershell
pnpm --filter @webnav/frontend exec tsc -p ../plugins/system-optimizer/tsconfig.json
node plugins/system-optimizer/build.mjs
```

源码位于 `src/`，构建会将固定 Windows 助手的 SHA-256 写入运行代码。插件运行不下载脚本、依赖或优化规则，不需要用户另装 PowerShell 模块；使用 Windows 自带 PowerShell 5.1，结构化请求经 stdin 传入，外部输入不拼成命令。

## 保存与卸载

数据由宿主提供的插件 dataDirectory 管理。每次系统写入先原子保存并刷新加密恢复记录，再执行；操作标识持久化，未知结果不自动重发。每次最多 50 项、同一时刻一项长任务、预览有效 5 分钟；保留最多 1,000 次恢复操作，达到上限阻止新增写入。恢复记录按页解密，插件激活不批量解密历史。记录内容不进入浏览器持久化、日志或普通目录备份。

停用撤销入口但保留记录；卸载保留安装文件和恢复数据，不自动反向修改系统。重装后可继续核对同机器、同用户的恢复记录；更换 Windows 用户或丢失其 DPAPI 密钥后不能保证解密。

## 验证范围

本机实际验收限 Windows 11 build 26200 x64 只读扫描与 DPAPI 测试数据加解密。系统设置及启动登记写入、冲突和恢复使用隔离适配器验证，尚未进行真实系统配置写入验收。不要把模拟写入通过描述为所有 Windows 构建均已验证。完整方案、来源及后续范围见仓库 `docs/system-optimizer.md`。
