# SSH 输出历史与查找

本文保留完整体验目标。当前已实现后端纯文本留存与独立历史对话框，以本节“当前实现”及 [WS 协议](websocket-protocol.md) 为准；后续细节与容量验收不应视为已完成。以前未保存的输出无法补录。

## 当前实现

- Cordis terminal-history 使用独立 SQLite 历史库，保存开始/结束时间、有序文本块与留存缺口状态。
- 跨块 UTF-8 和 ANSI 控制序列解析，单行状态最多 4,096 个 UTF-16 单元；不还原 TUI 屏幕，不双存原始录像。未结束的短行在换行或会话结束后保存。
- 默认保留 7 天、单会话 100 MiB、全局 1 GiB 文本；当前单会话到限暂停记录并标记缺口，全局与到期清理每分钟运行，磁盘余量不足暂停记录。仍需容量压测。
- 对话框默认最近会话，从首个保留块开始，固定上下界；查找、下一页、上一页与刷新，不实时追加。当前无命中位置跳转、相邻上下文专用查询或末页快捷键。
- 每页最多 100 块、200 KiB 序列化预算，扫描最多 400 块；只保留当前页与 100 个游标。关闭释放查询，过期或清理后提示刷新。
- 已用模拟 SSH 和集成测试验证固定范围、跨页搜索、清理提示及重启后读取；浏览器验证 4,500 行输出后仍可查询首行。下文为更完整的演进目标。

## 1. 最终交互

终端工具栏提供“查看历史”图标按钮，带可访问名称和悬停提示。点击打开独立的只读对话框，不在活动终端上拉补数据，也不把旧内容重新写进 xterm.js。

- 默认查看当前 SSH 会话；可切换同一服务器的其他已保存会话，按连接入口与开始时间区分。
- 顶部显示服务器、会话时间、记录状态和“截至已保存输出”的时间；提供搜索框、刷新和关闭图标。
- 默认从已保存记录的末页开始，支持更早/更晚翻页、选择复制。搜索覆盖该会话的整个快照范围，不局限于浏览器已加载页；结果显示命中片段，可定位其前后文。
- 打开时固定记录范围。继续输出不追加到对话框、不改变搜索结果、不自动滚动；只有点击刷新或重新打开才创建新的快照。切换会话也创建新快照。
- 关闭对话框回到原来的终端位置。对话框与实时终端没有输入绑定，历史内容不会被发送给 SSH。
- 空状态分别说明“尚无已保存输出”“此会话未开启记录”“没有匹配结果”“历史已清理”；加载失败可重试。记录中断或被裁剪时明确显示记录范围不完整。

历史对话框中只展示必要状态，不加入录屏、播放速度、时间轴或实时订阅。搜索默认 Enter 提交，刷新保留关键词但重新查询，旧请求结果不得覆盖新的会话或关键词。

## 2. 两份数据各自有上限

| 层次 | 用途 | 初始预算 |
| --- | --- | --- |
| 活动 xterm.js | 实时交互与近期滚动 | `scrollback = 2000`，沿用实时 ACK 与背压 |
| 历史对话框 | 阅读和搜索已保存的文本 | 当前页及相邻页，最多 1,000 条 / 2 MiB 文本，先达到者生效 |
| 本地 SQLite 历史库 | 会话文本及查询索引 | 最长 7 天、单会话 100 MiB、全局 1 GiB 文本负载，任一限制先达到即清理 |

上表是设计预算；当前实现额度与缓存策略见前文，尚未进行容量压测。记录条数不是终端屏幕行数；长输出可以拆成多个连续片段。文本预算也不等于 JS 堆、SQLite 文件、索引或 WAL 的实际占用，实施时另行监测文件大小、磁盘余量和内存。

按本次需求，正式 SSH 功能接入后默认启用有界输出记录，并提供连接级“保存输出历史”开关，在新会话创建时确定。关闭不删除既有记录，也不能补回关闭期间的输出。打开对话框本身不会开启记录。活动终端清屏或淘汰本地历史不删除已归档记录。

## 3. 记录什么

首版保存可搜索的纯文本转录和会话元信息，不同时保存原始 ANSI 字节流，不提供录像回放或逐帧还原。原始 SSH 输出仍按顺序完整传给活动 xterm，记录支路不改变实时字节流。

文本转录按输出顺序保留可打印内容，使用跨块 UTF-8 解码器及有界的控制序列状态机，不能对各个 WS/SSH 块独立做正则替换：

- CRLF 归一为一个换行，跨块也要正确；单独 CR 的进度更新作为新的文本片段，标注“回车重写”，不回头修改已归档记录。
- 保留换行、制表符；退格用可见操作标记表示，不承诺还原编辑后的命令行。颜色样式不保存。
- 丢弃 SGR 样式及 OSC/DCS 等非文本控制内容；不执行剪贴板、链接打开、窗口标题等指令。控制字符串持续未结束时也只维护有限状态，不累计整个字符串。
- 任意光标移动、清屏和 alternate buffer 进入/退出记录为合并的“屏幕操作”标记，避免产生无限控制标记。`vim`、`top` 等全屏程序只保留其可打印输出与标记，界面说明“文本记录，不还原原屏幕”。
- 单条 UTF-8 文本最多 8 KiB；无换行输出按完整字符拆成不可变片段，附逻辑行 ID、片段序号和连续标志。尾部普通文本按批次封存，因此不需要等一条无限长的行结束才能查历史。

每条记录提交后不可修改。搜索应识别同一逻辑行的连续片段，支持跨 8 KiB 分片的关键词；不得把不同会话、换行或屏幕操作两侧拼成一个命中。前端用文本节点和受控高亮渲染，不使用输出生成的 HTML，也不在历史对话框实例化可交互终端。

不主动记录键盘输入、SSH 认证密码或私钥。远端回显的命令、令牌或文件内容仍属于输出，不能保证自动排除秘密；连接设置应清楚标明会保存输出并允许关闭。历史仅放在本机用户数据目录、使用当前用户访问权限，不进入常规运行日志、普通 JSON 配置导出、源码或浏览器持久化存储；历史查询是专门受鉴权保护的正文读取能力。

## 4. 后端与生命周期

由 Cordis `terminal-history` 服务管理文本转录、批量落盘、查询和清理。SQLite 保存 `TerminalHistorySession` 与 `TerminalHistoryEntry`，以 `(sessionId, seq)` 建立索引，不引入文件归档与数据库之间的双写一致性问题。

会话元信息包含记录 ID、稳定的本机用户身份、服务器和连接 ID、开始/结束时间、记录开关、`recording/completed/interrupted/incomplete/disabled` 状态、保留起点及提交水位。历史归属不能只绑定短期浏览器 Cookie，自动重建本机会话后仍可读取保留的记录；设置了主密码则统一受解锁状态约束。

文本记录包含递增 `seq`、本地收到输出的时间、正文、逻辑行与片段标识、记录类型。时间用于展示，分页使用序号；不能用可能重复或回拨的时间戳充当游标。序号在 JSON 中使用十进制字符串。

归档在专用 worker 中解析与落盘，避免同步 SQLite 写入和搜索阻塞 SSH/WS 主事件循环。批次初值为 250 ms 或 64 KiB，先到先提交；每会话待归档队列最多 1 MiB，进程内总计最多 8 MiB。worker 通信、解析中数据及待提交批次都计入预算，不能用无界 `postMessage` 队列绕过限制。

快照只读取已提交记录，不为创建快照等待实时输出全部落盘。实时 `terminal.ack` 仅表示前端解析完成，绝不代表历史持久化完成；二者独立计量。

磁盘写入失败、空间不足或归档队列超限时，停止该会话归档、释放其待归档缓冲，标记“不完整，记录截至……”并通知会话状态；实时 SSH 继续遵守原有流控。不静默丢一段后继续标作完整，也不自动积压等待磁盘恢复。正常关闭等待有界时间提交尾批次；进程异常退出仅保证已提交且可恢复的记录，启动时将未正常结束的归档标为中断。

保留策略先清理过期记录，再清理最旧的已结束会话；仍超额时按序号裁剪活动会话最早的完整片段并更新保留起点。磁盘无法释放到安全余量则停止新写入。清理不能为了保住一个打开的对话框而无限延期；SQLite 删除、WAL checkpoint 与空闲空间回收也需设预算，不把“逻辑删除”视为磁盘文件立即缩小。

关闭网页或 SSH 会话只结束实时连接，已提交历史在保留期内仍可查询；重连创建新的 SSH 会话及历史记录。历史不会恢复 Shell，也不会自动连接服务器。

## 5. 固定快照、分页与搜索

打开时后端返回 `snapshotId`、`capturedAt`、`retainedFromSeq`、`upperSeq`、`recordingState`。其中 `upperSeq` 为当时最后一条已提交记录；所有查询都限定在这个闭区间内，新记录永远不混进旧快照。没有记录时序号边界为 `null`。

快照仅保存范围及鉴权信息，不复制整份正文，也不在用户阅读期间维持 SQLite 长事务。创建时在一次一致读取中取得保留起点与提交水位；每个分页或搜索批次在短读事务内核验保留范围并取数，清理记录与更新保留起点同事务提交，避免清理竞争造成静默漏项。初始有效期 30 分钟、每页面最多 2 个，绑定授权主体和当前业务 WS；关闭、断线或超时释放。服务重启或快照失效后由用户刷新创建新范围，不自动改变当前结果。

查询必须再次鉴权，服务端游标绑定快照、方向、搜索条件及最后序号。使用 keyset 分页，不用大 OFFSET；首次页面取快照末尾，结果内部始终按时间先后排列。默认 200 条，最多 500 条，同时限制响应序列化后的 UTF-8 JSON 大小为 256 KiB。前端去重并维护可见首条的序号锚点，淘汰较远页而不是累计所有访问过的页。

首版提供按会话的普通文本子串搜索，关键词最多 256 个 Unicode 码点；不提供正则或任意 SQL。对 SQL 做参数化，`%`、`_` 等作为字面字符。数据库 worker 按有限序号批次读取与匹配，不把整份历史下载到浏览器搜索；初始每批至多 200 条，每次请求至多扫描 2 MiB 文本或 100 ms，然后返回继续游标。搜索片段边界预留有限的关键词重叠区，避免遗漏跨片段命中。

每次最多返回 100 个命中和 256 KiB JSON，结果包含记录位置与短上下文；点击命中用同一快照定位正文页。搜索游标除序号外还须包含片段内偏移及有限的跨片段匹配状态，命中用 `(startSeq, startOffset, endSeq, endOffset)` 定位，偏移统一按 Unicode 码点计数；达到返回上限时可从同一片段继续，重叠扫描区不得重复返回已报告命中。未扫描完时返回 `done: false` 和 `nextCursor`，显示“查找中”，不能把空的中间批次当作无结果或声称已得出全量总数。每个对话框仅一个进行中的查询，关键词改变、切换会话或关闭后取消旧查询，并用本地查询代次忽略迟到响应。

清理策略造成快照范围中的任一记录已不可读取时，返回 `HISTORY_RANGE_EXPIRED` 和当前保留范围。前端停止翻页并提示刷新，不静默跳过缺失内容。已经加载到本页内存的旧文本可保持显示，但不能据此声称服务器仍保留完整快照。

## 6. WS 方法

全部使用现有 `/ws` 业务通道，按需请求，不轮询、不订阅历史正文，不建立 REST 接口。正文分页独立于 `/ws/terminal` 和终端 ACK。

| 方法 | 参数要点 | 结果要点 |
| --- | --- | --- |
| `history.sessions` | `serverId`、可选 `connectionId`、游标、限额 | 有权限的已保存会话及记录状态，最多 50 条 |
| `history.open` | 历史 `sessionId` | 固定快照信息，不创建远端连接 |
| `history.page` | `snapshotId`、游标或 `aroundSeq`、限额 | 文本页、前后游标、当前快照边界 |
| `history.search` | `snapshotId`、`query`、继续游标 | 命中、`nextCursor`、`done` |
| `history.cancel` | 进行中的请求 ID | 尽力取消本业务连接发起的扫描 |
| `history.close` | `snapshotId` | 幂等释放快照及其扫描 |

`history.open` 的资源数量有上限，超时重试不得泄漏快照；同一业务连接对同一历史会话再次打开时释放旧快照。只读 page/search 请求可按相同快照与游标重试；不影响连接启动方法的操作 ID 规则。未录制、记录未提交、记录不完整与记录已清理分别返回明确状态，不能都返回空数组。

历史响应受业务 WS 总发送预算限制，每个连接最多一份历史正文响应等待发送；目录、鉴权和普通控制消息优先。单个 WS 消息发送期间无法被其他消息抢占，所以必须同时限制正文响应大小，避免搜索拖慢管理操作。

## 7. 实施验收

- 前端滚动缓冲淘汰后，已保存文本仍能在历史对话框查询；关闭与重启后保留期内仍可查，未保存部分如实标记。
- 打开快照后持续输出，分页、搜索、命中上下文均不纳入新记录；手动刷新才改变截止位置。
- 覆盖跨块 UTF-8/CRLF/控制序列、超长无换行文本、跨片段关键词、中文、重复时间戳、全屏程序及非文本控制内容。
- 搜索未完成、无匹配、取消、迟到响应、WS 重连、权限撤销和保留策略清理均有明确行为；不能串会话或越过快照边界。
- 验证历史页缓存、worker 队列、磁盘和查询时限；高输出下历史查询不阻塞实时输入或改动 xterm 状态。
- 磁盘满、关闭超时和进程异常退出后记录状态准确；历史正文不进入运行日志或普通配置导出。

上述为完整验收清单。已完成范围以开头记录与自动测试为准，容量、长时间负载和更完整的上下文定位仍待验证。
