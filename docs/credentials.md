# 凭据保存

右上角齿轮打开“全局设置”，统一配置可选主密码与解锁有效期。默认不设置主密码，所有密码直接使用可逆编码保存，不出现首次保存方式选择，也不在各连接表单重复设置主密码。设置、修改或移除主密码时，所有已保存的 SSH 密码、私钥口令与 RDP 密码在同一事务中转换；失败则整体回滚。

编辑服务器中的“认证设置”可保存每个 SSH 入口的密码或本机私钥路径及口令。已保存秘密不会回填，留空表示保持原值；私钥口令可以显式清除。

RDP 的“登录密码”直接显示在入口的用户名下方，新入口也可填写，点击服务器的“保存”一起提交。密码使用独立的凭据表，目录与密码在同一数据库事务内提交；写入失败不会只保存一半。已保存的密码不回填，留空保留原值，也可勾选清除 WebNav 中的密码。密码编辑纳入未保存提醒，保存失败保留当前草稿，关闭或保存成功后释放，不写入浏览器持久存储。其保存方式始终跟随全局设置。

| 方式 | 落盘内容 | 启动后 |
| --- | --- | --- |
| 不设主密码 | 密码与私钥口令使用 Base64 可逆编码 | 直接使用，无需重复输入 |
| 使用主密码 | scrypt 派生密钥，AES-256-GCM 加密；随机 salt / nonce，凭据 ID 作为 AAD | 首次访问输入主密码，密钥仅在进程内；按有效期锁定，也可立即锁定 |

Base64 不是哈希，也不作为加密宣传。主密码不会写入数据库，保存的校验密文用于验证解锁。当前主密码长度为 8–1,024 字符；未提供找回主密码功能。

主密码有效期以整数分钟保存。下拉菜单提供 5 / 15 / 30 分钟、1 / 4 小时、1 / 7 天、永不过期，也支持自定义 1–525,600 分钟。默认永不过期；从成功解锁或保存有效期设置的时间开始计时，读取数据、刷新和新标签不会续期。有效状态在当前后端服务内共享；永不过期表示服务仍在运行就无需重输，服务重启仍需解锁。

页面先订阅全局解锁状态，已设置主密码且未解锁时只显示解锁对话框，解锁后再加载目录。到期由后端清除内存密钥并通过 WS 推送，所有已订阅页面出现解锁界面；业务 RPC 同时校验，不依赖前端计时。锁定不终止已经认证的 SSH 或已启动的 mstsc；未保存的编辑草稿保留在被遮盖的面板中，解锁后继续。连接断开或服务重启期间，有主密码的已加载页面也遮盖工作台。

解锁后可在全局设置中切换方式或更换主密码。备份和旧磁盘页不属于密码轮换或安全擦除承诺。主密码只加密应用保存的秘密，不改变原始私钥文件本身，也不加密目录元数据或终端历史。

导入本机 SSH 时保存 IdentityFile 的绝对路径，不复制私钥内容。首次使用前后端会读取并解析该文件；有口令的私钥需要在认证设置保存口令。OpenSSH config 不存储登录密码，因此导入不能凭空恢复 config 中不存在的密码。

认证通过 credentials 服务解析，不返回给目录查询、普通 JSON 导出或日志。SSH 独立认证表单的秘密在提交后及关闭时清空；RDP 编辑草稿在保存失败时保留，成功或关闭后清空。二者都不写入 localStorage / IndexedDB。远端输出可能回显秘密，历史不能承诺完全脱敏。

## Windows RDP 凭据交接

后端启动 RDP 时读取此入口的密码，通过固定 PowerShell 程序调用 Windows `CredWriteW`；用户名和密码只经标准输入的 JSON 传递，不拼接为脚本、不进入命令行或环境变量。写入当前 Windows 登录会话的 `TERMSRV/<host>` 通用凭据后再启动 mstsc。用户名与地址放在专用数据目录内的临时 `.rdp` 文件，文件不含密码，5 分钟后清理；应用退出清理残留文件但不结束 mstsc，启动时另清理超过一天的旧文件。

Windows 交接凭据采用 `CRED_PERSIST_SESSION`，在当前 Windows 登录会话中保留，注销后消失。应用主密码锁定或清除应用密码不会撤回已经交给 Windows 的副本。同一主机不同端口/账号共用 Windows 的主机凭据槽，采用最近交给 Windows 的账号密码；不承诺同主机多账号同时启动时的独立认证。远端策略要求再次输入密码或其他认证时由 mstsc 处理，不修改系统认证策略。

实现依据：[CredWriteW](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credwritew)、[CREDENTIALW 与登录会话保留范围](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw)。目前已验证 Windows API 写入、读取与清理随机测试凭据，模拟启动验证调用顺序；未对真实服务器执行 RDP 登录。
