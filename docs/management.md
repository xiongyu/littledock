# 管理页

## 当前范围

从侧栏“管理中心”进入，开发地址为 `http://127.0.0.1:5173/#manage`。管理页与导航共用当前页面的目录，保存后立即反映在侧栏、目录和收藏夹中。

目录通过业务 WS 保存到后端 SQLite，刷新与重启后保留；初始没有示例数据。外观设置和背景图片保存在浏览器，与目录配置分开。SSH、凭据和历史查询已接入，真实连接由后端发起。

## 服务器与连接入口

服务器表格支持搜索、分组和协议筛选。搜索匹配名称、地址、备注、分组名、标签和连接名称；选中父分组时包含后代分组的服务器。点击名称或铅笔图标打开编辑抽屉。

- 添加、修改和删除服务器；编辑使用独立草稿，删除需要确认。
- 从导航分组页新增时，草稿默认归入当前分组；从管理中心新增时，默认使用当前分组筛选。全部目录、收藏、最近使用或全部分组筛选下默认未分组。默认值只在新建时使用，手动选择、已有记录和复制记录的所属分组优先，不按协议或分组名称猜测归属。
- 复制创建新的服务器和连接 ID，保留其资料与入口，但取消收藏，随后打开编辑抽屉。副本在点击复制时已经加入目录，取消编辑仍保留副本。
- 勾选服务器后，选择目标分组并点击移动图标批量调整归属，也可批量删除。表头全选仅选择当前筛选结果；改变筛选或管理类别会清空选择。
- 收藏通过编辑抽屉设置，也可在导航中切换。服务器删除时一并移除其连接入口与收藏。

服务器资料包括名称、IP 或主机名、所属分组、标签和备注。地址不包含协议、端口或路径；支持 IPv4、IPv6 和主机名。端口在具体连接入口中填写。服务器名称最多 60 字，最多 12 个标签且每个最多 30 字，备注最多 500 字。

每台服务器需要 1 到 12 个连接入口，允许同类型重复，例如两个 SSH 入口分别使用不同用户名或端口。每个入口有独立 ID 和名称，名称最多 30 字。

| 类型 | 当前可编辑配置 | 当前行为 |
| --- | --- | --- |
| SSH | 名称、端口、用户名、保存输出历史 | 打开网页终端；新会话按历史开关保存输出 |
| RDP | 名称、端口、用户名、登录密码、打开方式、域、认证与证书选项、显示模式、分辨率 | 网页内嵌，或按入口设置启动 mstsc；原生只显示客户端启动结果 |
| VNC | 名称、端口、VNC 密码 | 后端认证，网页 noVNC 工作区 |
| 网页 | 名称、完整 HTTP / HTTPS URL | 从 URL 推导端口，保留路径；用户点击打开网页 |

端口必须是 1–65535 的整数。网页 URL 不接受其他协议、空白、控制字符或内嵌用户名和密码。已有 SSH 入口的“认证设置”提供密码、私钥路径和口令保存；新入口先保存目录，再设置认证。详见 [凭据](credentials.md)。

RDP 登录密码直接在入口中填写，随服务器保存，新入口无需先保存一次；需要填写用户名。密码最多 1,280 个 UTF-16 单元，不接受 NUL，不去除密码中的空格。留空不更改已有密码，已保存时显示标记；显式清除只删除 WebNav 中的密码。所有连接遵循右上角“全局设置”：未设主密码默认编码保存，设定后统一加密，访问页面时统一解锁。密码通过单独的 WS 参数提交并存入凭据表，不进入目录对象或 JSON 导出。

### RDP 显示设置

`rdpClient` 可选 `browser` / `native`；省略时默认网页内嵌，包括旧记录及旧格式导入；只有显式 `native` 使用系统客户端。前后端与编辑表单使用同一默认规则，无需修改旧记录或重新保存密码。网页 RDP 的 `rdpOptions` 保存可选 `domain`、`security`（any/nla/tls/rdp）、`certificate`（verify/tofu），拒绝未知字段或枚举。网页窗口最大 4096 × 2160，不支持多显示器，全屏可通过桌面工具栏触发。下文 8192 上限及 mstsc 文件适用于原生模式。VNC 密码与 RDP 密码同样随服务器事务保存，无需用户名；兼容范围见[网页桌面](embedded-desktops.md)。

每个 RDP 入口单独保存显示设置，同一台服务器的多个桌面入口也可以使用不同配置：

- **默认**：网页使用固定 1920 × 1080，表单显示“默认 · 1920 × 1080”；系统模式显示“跟随客户端”，保持 mstsc 默认行为。已有明确分辨率继续沿用，目录无需迁移或批量重写。
- **窗口 · 指定分辨率**：下拉选择常见分辨率（包含 1080p、1440p、超宽屏和 4K），或选择“自定义”填写宽高。宽高各为 200–8192 的整数像素，启动后保持指定的桌面分辨率。
- **全屏 · 单个显示器**：使用单屏全屏，分辨率跟随所在显示器。
- **全屏 · 所有显示器**：使用本机所有显示器，分辨率跟随各个显示器。

显示模式互斥，全屏模式不携带窗口宽高。修改只影响下次启动，不调整已经打开的 mstsc 窗口。未保存用户名或密码时同样可以使用显示设置。保存、复制、导入导出和服务重启均保留各入口配置。

`rdpDisplay` 是 `schemaVersion: 1` 的可选 RDP 专属字段；省略时网页为固定 1080p、系统模式跟随客户端，已有记录不需要数据库迁移。窗口模式为 `{"mode":"windowed","width":1920,"height":1080}`，单屏全屏为 `{"mode":"fullscreen"}`，所有显示器为 `{"mode":"multimon"}`。网页单屏全屏模式可向支持 Display Control 的服务器请求跟随视口尺寸；多屏仅适用于系统模式。前后端共用校验，拒绝未知模式、非整数或越界尺寸、全屏混入宽高以及其他协议携带此字段。旧版程序不识别新字段，回退程序版本前需移除此字段。

后端按 [Microsoft RDP 显示属性](https://learn.microsoft.com/en-us/azure/virtual-desktop/rdp-properties#display-settings) 写入受控临时 `.rdp` 文件：`screen mode id`、`use multimon` 和窗口模式的 `desktopwidth` / `desktopheight`；窗口模式同时设置 `dynamic resolution:i:0`。这些参数不经 shell 拼接，也不更改全局 `Default.rdp`。

### 编辑与关闭

- 新增和编辑服务器的删除、取消、保存操作固定在面板标题下方；只有下方表单滚动，滚动到任意入口时仍可直接保存或取消。新增时不显示删除。
- 浏览器已验证表单滚到底部后操作栏坐标不变，并通过顶部按钮完成保存；见[固定操作栏截图](design/screenshots/editor-fixed-actions.png)。
- 只有在抽屉外遮罩上按下并原地松开才视为点击空白关闭；从输入框拖选文字到外面松手、从外部拖入或拖动遮罩都不关闭。
- 关闭按钮、取消、Esc、点击遮罩、Ctrl K，以及切换认证设置或历史面板，统一检查编辑草稿。未修改或已改回原值时直接离开；有修改时提示“保存 / 不保存 / 继续编辑”。
- “保存”执行同一套表单校验并等待后端确认，成功才离开；校验失败、断线或保存失败都保留草稿并显示错误。保存过程中锁定编辑与关闭，防止重复提交或丢失等待期间的新输入。
- 确认框中的 Esc 和关闭按钮都等同“继续编辑”；点击确认框外不丢弃草稿。此交互保护适用于应用内关闭编辑抽屉，不替代浏览器刷新或关闭标签页。

## 分组

分组页左侧为目录树，数字只统计直属服务器；右侧编辑名称和上级，也可创建新分组。顶部搜索在此页匹配分组名称。服务器可不属于任何分组，统一显示为“未分组”。

- 最多 5 层，从顶层开始计数。更改上级时，子分组和所属服务器跟随保留。
- 分组名称最多 40 字，同一上级下不允许重名，比较时忽略大小写。
- 上级必须存在，不能选择自身或后代；整棵树校验也会拒绝循环和超过 5 层的移动。
- 删除分组需确认：直属服务器移到未分组，直接子分组提升到被删除分组的上级，其后代结构保持不变；不会连带删除服务器。
- 如果子分组提升后与同级已有名称冲突，整个删除不生效，需先改名或调整分组。

当前没有拖拽排序、批量删除分组或分组自动折叠功能。

## JSON 导入与导出

管理页右上角上传图标打开导入对话框，可选择文件或粘贴 JSON。选择文件后自动校验并显示预览；粘贴后点击“校验并预览”。校验成功时显示服务器和分组数量变化，以及前 8 台服务器的名称与地址。

只有点击“确认替换目录”才应用导入。导入采用整体替换，不合并；未包含的原目录记录会被移除，尚未导出的修改不会保留。修改输入文本或重新选择文件会清除旧预览；读取文件时禁用确认，避免误用上一次预览。校验失败或取消时不更改目录，导入成功不自动启动连接。

下载图标导出当前完整目录为 `webnav-config.json`，不受表格筛选或勾选影响。使用紧凑 JSON，保证合规目录的导出文件也在导入大小上限内。文件只包含分组、服务器与允许的连接配置，不包含外观图片、浏览器会话、最近连接、凭据、主机信任记录或输出历史。当前导入预览、版本检查、事务保存和导出均走已鉴权的业务 WS。

当前格式为 `schemaVersion: 1`。新增、复制、编辑和导入共用目录上限：最多 200 个分组、2,000 台服务器，整个目录序列化为紧凑 JSON 后的 UTF-8 大小不超过 1 MiB。导入文件或粘贴文本本身也不超过 1 MiB。这些是校验边界，不代表已经完成相应规模的性能验收。校验字段类型、允许字段、ID 唯一性、分组引用、层级和连接参数；未知字段或连接类型会拒绝导入，密码与私钥字段也不会被接受。

```json
{
  "schemaVersion": 1,
  "groups": [
    { "id": "development", "name": "开发环境" },
    { "id": "tools", "name": "工具", "parentId": "development" }
  ],
  "servers": [
    {
      "id": "dev-node",
      "name": "开发节点",
      "host": "192.0.2.10",
      "groupId": "tools",
      "tags": ["Linux"],
      "note": "文档示例",
      "favorite": true,
      "connections": [
        { "id": "ssh-dev", "type": "ssh", "name": "SSH", "port": 22, "username": "developer", "saveHistory": true },
        { "id": "ssh-admin", "type": "ssh", "name": "管理 SSH", "port": 2222, "username": "admin", "saveHistory": false },
        { "id": "web-admin", "type": "web", "name": "控制台", "port": 443, "url": "https://192.0.2.10/admin" }
      ]
    }
  ]
}
```

顶层分组省略 `parentId`；未分组服务器使用 `groupId: ""`。所有 ID 只能包含字母、数字、横线和下划线，最多 100 字。分组 ID 和服务器 ID 各自在对应集合内唯一，连接 ID 在所属服务器内唯一。分组 ID 禁止使用页面保留值 `all`、`manage`、`recent`、`favorites`。SSH 未提供 `saveHistory` 时按 `true` 解析；网页 `port` 必须与 URL 一致，未显式写端口时 HTTP 为 80、HTTPS 为 443。

当前数据库保存带版本号的嵌套目录文档，凭据另表保存。格式变更必须显式迁移版本。

## 测试路径

以下是建议手动核验步骤，完整验证状态以本文末尾记录为准。

1. 添加测试服务器，配置两个 SSH 和一个网页入口，保存后重新打开检查，再取消一次编辑确认原值保留。
2. 复制服务器，确认副本可独立修改；组合搜索、分组和协议筛选，再批量移动与删除选中项。
3. 新建父子分组，更改上级；尝试同级重名、超过 5 层和删除后重名，检查错误提示及目录保持不变。
4. 删除有直属服务器和子分组的分组，确认服务器进入未分组，子分组提升一级。
5. 导出配置后导入，先核对预览再确认；尝试无效 JSON、错误引用和不支持的字段，确认失败不改变当前数据。
6. 检查空目录、无搜索结果和窄屏操作；刷新并重启后端后，确认目录仍然保留。
7. 在编辑抽屉内拖选文字并到遮罩上松手，确认不关闭；修改后分别通过关闭按钮、取消、Esc、遮罩和 Ctrl K 离开，检查三种选择。校验失败或后端断开时尝试保存，确认草稿保留；改回原值后关闭不再提示。

自动化逻辑测试位于 `frontend/tests/`，其中 `dialog-backdrop.test.mjs` 覆盖遮罩点击、跨面板拖选、拖动回原位、取消手势和非主指针。只检查前端时运行 `pnpm --filter @webnav/frontend test`、`pnpm --filter @webnav/frontend build`（包含类型检查）；从仓库根目录运行 `pnpm test`、`pnpm typecheck`、`pnpm build` 可检查整个项目。后端另有集成测试覆盖事务、鉴权、持久化和模拟 SSH。

## 本机 SSH 导入

“导入本机 SSH”读取当前用户 ~/.ssh/config，解析 Host、HostName、User、Port、IdentityFile 以及通配默认项；相同地址、端口、用户名和身份文件的别名合并，按网段分组。私钥保留在原路径，导入事务保存引用。遇到 Include / Match 会明确拒绝；代理、跳板和变量入口提示跳过，不执行配置中的命令。导入采用完整替换，不自动连接，也不从用户名推断 Windows 或添加 RDP。
