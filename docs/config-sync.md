# 配置同步（内置插件）

状态：2026-10-27 已实现首版。入口在「全局设置 → 配置同步」，也可从插件中心的内置「配置同步」打开。下面说明当前契约及明确标注的后续范围。真实 GitHub / Gitee 仓库尚未上传验收；测试使用独立本机 bare Git 仓库，不接触用户真实配置。

## 开始使用

1. 在 GitHub 或 Gitee 准备一个可读写的仓库，推荐专用私有仓库，并准备仓库访问令牌。本机需要安装 Git。
2. 保存平台、仓库地址、平台用户名、分支与空间编号。新空间使用生成的编号；其他电脑填写相同的地址、分支和编号。令牌可以仅本次使用，设置本地主密码后才能持久保存。
3. 选择「新建同步空间」或「连接已有空间」，填写自定义同步账号与至少 12 个字符的同步密码。密码丢失无法通过仓库账号找回。
4. 点击「立即同步 / 预览差异」，核对合并方式及变更，再「确认并同步」。首次上传会说明服务器与收藏数量；冲突逐条选择后点击「更新预览」。
5. 自动同步默认关闭，首次成功后可在同步设置中开启。保存设置会锁定同步空间，重新解锁后生效。

上传结果不明时使用「核对待处理操作」；只有用户明确选择「核对后重送原提交」且远端仍为预期版本时才重送。新恢复的 Local / ADB / 第三方入口先检查本机配置，再确认绑定。插件恢复清单只作为安装参考，不自动执行代码。

## 产品与默认行为

新增内置「配置同步」插件，使用用户自己的 GitHub / Gitee 私有仓库保存加密配置。配置在运行 WebNav 的本机后端加密后上传，在另一台电脑的本机后端解密；平台不接收同步密码和配置明文。首版一个本地配置档案连接一个同步空间，不做多平台同时写入。

「同步账号 + 同步密码」由用户自定义，不需要注册 WebNav 账号，也不要求与 GitHub / Gitee 账号一致。仓库访问令牌用于读写文件，同步账号和密码共同派生解密密钥。只有仓库令牌不能解密，只有同步账号密码也不能定位或访问未知的私有仓库。新电脑需要仓库地址、分支、同步空间编号、仓库访问权限以及同步账号密码。

同步账号是加密标识，不是第二重身份认证。安全性主要依赖足够强的同步密码；拿到密文的人可以离线尝试密码，界面限速不能阻止这种尝试。

默认手动同步；建立共同基线后可开启自动同步。首次接入、冲突、整库覆盖和历史恢复均先预览。同步不会自动连接服务器、启动本地命令、安装插件或恢复正在运行的终端。

## 同步范围

| 内容 | 首版策略 | 恢复规则 |
| --- | --- | --- |
| 分组、服务器、连接入口、收藏、排序 | 默认同步 | 保留稳定 ID，完整校验层级和引用 |
| 网页收藏的名称、网址和备注 | 默认同步 | 不含截图缓存 |
| 终端配色与入口的配色引用 | 默认同步 | 配色与引用一起验证 |
| SSH / RDP / VNC / WDB 密码、网页收藏账号密码、私钥口令 | 单独勾选，默认关闭 | 在后端按目标电脑的本地主密码设置重新保存，不回传浏览器 |
| 私钥文件、本机 ADB 授权文件 | 不同步 | 新电脑手动绑定已有文件或重新授权 |
| Local 工作目录、自定义 Shell 路径、SSH 私钥路径、ADB 设备编号 | 作为本机绑定保留，不进入便携快照 | 新电脑显示「需要绑定本机资源」；保留原电脑绑定 |
| PowerShell / CMD、RDP 系统客户端等系统相关选项 | 保留配置含义 | 本机不支持时提示重新选择，不静默换成其他命令 |
| 插件仓库、插件 ID、锁定版本 | 可选，仅恢复清单 | 缺少的插件显示待安装，沿用正常安装与风险确认流程 |
| 插件代码、启用状态和任意插件配置 | 不自动应用 | 不导出整个插件注册表；以后按声明的便携字段接入 |
| 浏览器外观、壁纸、工作区布局 | 第二阶段 | 当前只在浏览器保存，需要显式采集和应用 |
| 主机指纹、RDP 证书信任、Cookie、会话票据、主密码校验材料、仓库令牌、同步密码 | 不同步 | 新设备独立确认信任和授权 |
| 输出历史、运行会话、截图、缓存、编辑中的文件、日志 | 不同步 | 与配置同步分开管理 |

需要专门的便携快照结构，不能直接上传数据库或现有普通 JSON 导出。Local / ADB 入口可以保留名称与选项，但本机资源未绑定时不能启动；已有本机绑定按入口 ID 复用。

关闭「参与凭据同步」表示本机不上传或应用凭据变化，不能解释为清空云端密码；云端已有凭据部分原样保留。删除连接或收藏时，关联凭据的删除随该条目出现在预览中。首版没有一键清除云端所有密码；需要不含凭据的独立副本时，可关闭该选项并创建新空间。旧空间和 Git 历史不会因此被删除。

## 加密与密码生命周期

采用固定版本 `hash-wasm 4.12.0` 的 Argon2id，以及 Node.js 的 HKDF-SHA-256 / AES-256-GCM。Argon2id 在独立工作线程中运行，结束后终止线程；不在主服务线程上阻塞终端。不同步本机 Base64 保存格式或现有凭据密文。

1. 同步账号采用 NFC 规范化并去除首尾空白，区分大小写，创建前显示最终值；密码按原样处理，不 trim、不改变 Unicode。输入设长度上限并拒绝无效 Unicode。
2. 固定用途标识、账号和密码以明确长度前缀编码成 Argon2id 输入；每个空间及每次换密码生成新的 16 字节随机盐。初始配置为 64 MiB 内存、3 次迭代、4 路并行、32 字节输出，采用 RFC 9106 的受限内存推荐配置；实际耗时需在支持平台测量。[RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html#section-4)
3. 每次生成随机快照 ID，通过 HKDF 派生快照专用内容密钥；AES-256-GCM 使用新的 12 字节随机 nonce 和 16 字节认证标签。不得以时间戳代替随机数，不复用快照 ID / 密钥 / nonce 组合。
4. 固定格式头包含版本、算法、KDF 配置编号、随机盐、随机空间 ID、密钥代次、快照 ID 和 nonce；格式头的原始编码字节作为 AAD 一起认证。头部不包含同步账号或业务名称。正文包含配置、范围、父快照摘要及操作 ID，全部加密。
5. 解密前校验头部长度、字段和允许的 KDF 配置；拒绝未知算法、超大内存参数和超限载荷。认证成功后才解析正文，任何错误均不修改本地数据；提示不分别暴露账号或密码是否匹配。

使用认证加密使密文或格式头被修改时解密失败，算法实现选择遵循 [OWASP 加密存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)。首版不压缩，拟定明文最多 4 MiB、封装最多 8 MiB；目录自身仍遵守现有 1 MiB 校验。这是产品额度，不是平台配额或实测容量。

同步密码与派生根密钥只驻留后端内存；页面提交后清空密码字段，不写入普通配置、操作缓存、日志、浏览器存储或磁盘临时文件。首版不提供永久记住同步密码或开机自动解锁。默认解锁 30 分钟，「本次服务运行期间」是显式选项。全局主密码锁定、手动锁定、到期、插件释放和服务退出均清理密钥与明文快照，停止新操作。自动同步只在本地访问与同步空间均已解锁时运行。清理可控缓冲，但不宣称 JavaScript GC、交换文件或系统转储能被安全擦除。

仓库令牌默认仅本次使用；设置本地主密码后才允许持久保存，通过新增的凭据服务插件秘密接口管理并参与主密码迁移。令牌不进入公开 `configFields`，不随配置同步。移除本地主密码时明确清除持久令牌或改为本次使用，不静默降级成 Base64 长期保存。同步账号可以在本机显示和记住，但不传给存储平台。

修改同步账号或密码时，用新的盐、根密钥与代次重新加密当前完整快照，按远端版本条件提交；其他电脑下次同步必须重新解锁，不能用旧密钥覆盖新代次。历史版本保留原代次，查看时可能需要对应旧密码。**修改密码不能让 Git 旧提交、已下载副本或克隆失效。** 旧密码泄露后还需轮换其中保存的真实服务器凭据；可以另建同步空间并重新授权，但不能承诺撤回已有副本。

不设计平台代管密钥或密码找回。忘记同步账号密码后，若仍有可用的本机配置，可以创建新空间重新加密；不能仅凭 GitHub / Gitee 登录恢复旧密文。保护目标是上传内容和远端存储，已解锁电脑、恶意本机程序或具有完整宿主权限的插件不在此保护范围内。

## 存储与平台接入

首版支持 GitHub 与 Gitee，推荐专用私有仓库；共用 Git over HTTPS 传输，平台适配负责地址校验、认证方式与错误信息。以后可增加 GitLab、WebDAV、S3 等，必须满足版本条件写入与历史读取契约，不能把普通覆盖上传当作可靠同步。不将 GitHub REST 的版本语义直接套用到 Gitee。

默认使用专用 `webnav-sync` 分支，只管理 `spaces/<随机空间ID>/snapshot.wnsync`。每次成功同步生成一个提交，历史保存旧密文；不生成包含服务器名称、IP、同步账号或变更明细的明文索引。使用固定中性提交说明与应用提交身份，不读取用户全局 Git 作者邮箱。平台仍可看到仓库所有者、推送者、时间、次数和密文大小。

存储适配器约定：

- `readHead`：读取精确分支版本与密文，区分不存在、无权限、网络失败、损坏和超限。
- `publish(expectedVersion, candidate)`：仅当分支仍等于预期版本时提交；返回新版本、冲突或结果未知。
- `listVersions(cursor)` / `readVersion(version)`：分页读取历史及指定版本，不自动下载全仓历史。
- 网络操作支持取消、超时、字节与磁盘预算；同一空间只运行一个任务。

Git 候选提交必须以已读到的远端提交为唯一父提交，保持其他目录内容不变。提交时以精确预期 ref OID 做条件更新；若采用 `--force-with-lease=<完整ref>:<预期OID>`，必须同时验证上述父提交关系，不能借此改写历史。禁止 `--force`、无明确期望值的 lease、镜像推送和删除分支。远端变化时重新读取、解密、合并并生成预览，不对密文做 Git 文本合并。条件写入依据见 [Git push 文档](https://git-scm.com/docs/git-push)。首次创建分支也要求预期不存在；已存在却读不到不能当成空仓库。

GitHub 使用具备目标仓库读写权限的访问令牌；Gitee 使用平台支持的 HTTPS 凭据，启用双因素认证后需私人令牌。[Gitee 官方说明](https://blog.gitee.com/2026/07/14/gitee-%E5%8F%8C%E5%9B%A0%E7%B4%A0%E8%AE%A4%E8%AF%81%EF%BC%9A%E4%B8%BA%E4%BB%A3%E7%A0%81%E8%B5%84%E4%BA%A7%E5%8A%A0%E4%B8%8A%E7%AC%AC%E4%BA%8C%E6%8A%8A%E9%94%81/) 界面提供各平台权限说明，不承诺令牌粒度完全一致。只读检查成功不代表有写权限，首次实际提交才确认写入结果；保护分支拒绝写入时提示原因，不放宽保护。

使用插件数据目录内隔离的 bare Git 缓存，只放密文对象；不 checkout，不运行子模块、仓库脚本、钩子、外部过滤器或用户全局 Git 配置。令牌通过受限凭据辅助通道提供，不嵌入 URL、参数、环境变量、配置文件或日志；拒绝带 userinfo 的仓库地址。首版只接受平台官方 HTTPS 地址，不跟随跨主机认证重定向。子进程隐藏窗口并随任务或插件释放回收。

缓存预算为 128 MiB，运行时每 500 毫秒检查磁盘占用；单条 Git 命令最长 60 秒，输出、对象与历史页数另有限额。它不是严格的瞬时磁盘峰值或网络流量保证。超限保留配置并报告，不自动改成无界下载。加密全量快照难以去重；首版不自动改写或清理远端历史，也没有仓库用量图表，可另建空间归档。历史每页 20 条、最多浏览 120 条，提交结果核对最多追溯 128 条。平台令牌、保护分支、限流仍需用真实测试仓库验收。

## 同步、冲突与失败恢复

每台电脑维护上次成功同步的共同基线 B、当前本地快照 L、当前远端快照 R。基线与待提交候选以加密形式保存在本机，不另存含秘密的明文 JSON。锁定后只保留不含配置值的任务状态和远端版本标识。

| 情况 | 行为 |
| --- | --- |
| L、R 均未改变 | 显示已同步，不生成提交 |
| 只有 L 变化 | 条件上传，成功后更新基线 |
| 只有 R 变化 | 手动模式先预览后应用；自动模式按下述规则处理 |
| 双方修改不同记录 | 按稳定 ID 做三方合并，通过全部约束校验后可合并 |
| 双方不同地修改同一记录、删除与修改相遇 | 进入冲突页，逐条选择本机或云端，不按时间戳猜赢家 |
| 首次接入，没有共同基线 | 展示合并、采用本机、采用云端的差异预览；确认后建立基线 |

合并单位是分组、服务器元数据、单个连接入口、单个收藏、单个配色和对应凭据块，不做密文或密码字符串合并。双方结果相同不算冲突。分组父子关系、同级重名、排序、连接归属和配色引用跨记录校验；违反约束也进入人工处理。首次发现 ID 相同但对象不同按冲突处理，不静默生成重复入口。

自动同步默认关闭，首次建立基线后可开启：本地保存后 30 秒防抖，远端每 5 分钟检查一次并加入抖动；只自动应用无冲突、无删除的更改。涉及删除、整库替换、范围调整、本机绑定或历史恢复时暂停并显示预览。凭据只有明确加入同步范围后才参与自动应用。限流或网络错误退避，最多保留一个待同步标记，不累计任务队列。

预览只返回名称、公开字段差异、数量、凭据存在/变更标志及待绑定项目，不返回密码或完整解密载荷。一次最多展示 200 项，未解决冲突优先，更新预览后继续处理；总差异数和删除提示覆盖全部记录。后端票据绑定本机会话、各模块状态摘要、远端提交、同步范围和选择结果，5 分钟有效。确认时重新校验状态与解锁，发生变化就重新预览。

本地应用在同一数据库事务内保存目录、收藏、配色、重新加密的凭据及同步锚点，异常整体回滚。各模块校验和通知仍由其服务负责，成功后才推送订阅。已建立的终端/桌面不重连，后续连接使用新配置。

远端提交与本地数据库不能共享事务，因此持久保存操作 ID、候选密文、预期/候选版本及「待提交 / 远端已确认 / 待本地应用 / 完成」状态。双端合并先形成可应用候选并验证本地版本，再提交远端；本地应用前再次校验版本。若本地又改变或落盘失败，保留候选并显示待处理，不覆盖新变化，不提前将基线标成完成。

上传超时为「结果待确认」：重读远端，核对候选提交、认证后的操作 ID / 密文摘要，必要时有界查找其是否已成为新提交的祖先。证实成功才继续；不能确定时保留待处理状态，不能重新生成上传。明确未写入且远端仍为预期版本时，可重送同一候选。锁定/退出可能发生在提交之后，重启解锁后按日志核对；取消请求不等于撤回远端写入。

有效旧密文也能通过认证，加密不自动防止回滚。本机记录最后接受的提交与认证后的父快照链；分支倒退、历史断裂或空间 ID 异常时停止自动应用。新设备没有可信锚点，不能仅靠密码证明云端内容最新。恢复历史须显式选择并预览，再将旧配置保存为新的当前提交，不重置分支；旧代次快照须先用对应密码解密。

## 用户界面

全局设置新增「配置同步」，插件中心内置项提供打开入口，页面分四组：

1. 存储位置：GitHub / Gitee、仓库地址、分支、同步空间，高级项折叠。「检查连接」只检查访问，不创建或覆盖文件。
2. 同步账号：自定义账号、密码、首次确认密码、解锁时长。新建空间与连接已有空间明确区分，解锁后只显示状态和锁定按钮。
3. 同步内容：默认配置项、可选保存密码与插件恢复清单。说明本机不可迁移内容，首次成功后可开启自动同步。
4. 同步状态：上次成功时间、待同步变化数、当前步骤与可处理错误。主要操作为「立即同步」「历史版本」「锁定」。

新电脑流程：「填写存储位置 → 输入同步账号密码 → 预览合并 → 确认恢复 → 补齐本机绑定」。可复制不含令牌、同步账号或密码的存储定位信息；没有中心服务，不提供只输入账号就搜索仓库的功能。

冲突页并排显示本机与云端值，密码只显示「已更改」并选择来源；窄屏改为上下排列。目录尚未加载、无权限、未解锁、空空间、损坏密文、版本不兼容分别显示；断网保留已知状态，不把错误当空目录。

## 接入当前代码

服务能力与前端插槽有白名单，公开插件配置不接受秘密；首版已增加如下宿主接口。现有机制见[插件规范](plugins.md)、[凭据](credentials.md)、[管理页](management.md)和[WS 协议](websocket-protocol.md)。

| 位置 | 当前职责 |
| --- | --- |
| `backend/plugins/builtin.configSync/` | 内置元数据，主分类 `backup`、次分类 `exchange` |
| `shared/src/plugins.ts` 与插件管理器 | 新增 `service:configSync` 及内置名称/分类，默认在线替换；同步解锁或任务运行时等待，锁定同步且任务结束后自动生效 |
| `backend/src/plugins/config-sync/` | Cordis 编排、加解密、Git 适配、基线/冲突、任务状态、生命周期清理 |
| 核心存储与各业务服务 | 受控的便携快照读取/校验/事务应用入口，不直接复制数据库或绕开服务修改私有表 |
| 凭据服务 | 后端限域秘密导出/导入及插件令牌保存，参与主密码迁移；不增加浏览器明文导出接口 |
| `frontend/src/components/ConfigSyncPanel.vue` | 状态、设置、预览、冲突、恢复；显式注册专用设置面板，不扩展任意动态页面框架 |
| `shared/src/config-sync.ts` | 公开状态、设置与预览 DTO，私有凭据载荷类型留在后端 |

当前 `storage.replace` 会清理已删除连接的凭据，不能先替换目录再逐个导入秘密，必须先形成整体事务计划。不能调用浏览器用的 `bookmarks.reveal` 循环导出密码。内置服务秘密访问仅用于本次已选择范围的后端任务。

所有业务动作走已鉴权 WS：`configSync.status / watch / configure / check / unlock / lock / preview / apply / recover / history / rotatePassword / confirmBinding`；历史恢复使用 `preview` 的 `mode: restore`。它们是内置宿主 RPC；第三方扩展仍通过 SDK 的 `plugin.<id>.*` 注册。有副作用的方法带操作 ID；仅保存有界 HMAC 去重标记，不把请求正文或解锁密码放入通用结果缓存。重复 ID 返回 `SYNC_ALREADY_REQUESTED`，应读取状态或核对待处理操作；同 ID 不同内容返回 `OPERATION_CONFLICT`。前端不直接请求平台，不新增 HTTP REST 业务接口。

锁定、配置变更和销毁时取消定时器、网络请求、凭据辅助通道及 Git 子进程，清理可重复执行。暂停同步不删除本地配置、仓库或历史。插件未配置时空闲，不自动扫描账号或仓库。

## 实施顺序与验收

首版已接入 GitHub / Gitee 地址与认证、手动加密同步、可选凭据、差异预览、三方冲突、历史恢复、账号密码更换及可选自动同步。浏览器外观、可审核的插件便携配置、其他存储和云端凭据批量清除属于后续范围，私钥文件迁移不在首版内。

必须验证：

- 密码学测试向量、账号编码、错误密码/账号、截断、篡改、随机数与恶意 KDF 头；上传文件、Git 缓存、提交信息和日志不出现测试秘密。
- GitHub / Gitee 测试仓库的创建、读取、令牌失效、只读权限、保护分支、并发条件提交、提交后断网、重启核对和历史分页；本机 Git 测试不等于平台验证。
- 双机同条目冲突、删除与修改、同名分组、引用失效、首次合并、切换范围、未加载目录及跨系统绑定。
- 目录/收藏/配色/凭据事务失败回滚、不同本地主密码下恢复、不参与凭据同步时保留秘密、删除条目时关联秘密一并预览。
- 自动同步防抖、限流退避、锁定/退出发生在上传前后、预览过期、旧代次设备写入、有效旧密文回放与本机锚点丢失。
- 主要界面流程、失败与空状态、窄屏；禁用插件或关闭任务后无遗留进程、明文缓存或定时器。

当前 10 项专项自动测试覆盖加密边界、恶意格式、两端恢复与冲突、Git 条件写入、受限令牌辅助通道、上传响应丢失、重启核对、历史回放拒绝、更换密码与旧版本恢复、事务回滚、主密码迁移和 WS 去重。浏览器在隔离数据目录验证设置、首次上传、历史列表、错误密码、插件入口及 390px 布局；[桌面截图](design/screenshots/config-sync.png)、[窄屏截图](design/screenshots/config-sync-mobile.png)仅包含测试数据。

本次类型检查与生产构建通过；完整回归为后端 92 项、前端 42 项，共 134 项通过。生产构建中的独立密钥工作线程另行验证。
