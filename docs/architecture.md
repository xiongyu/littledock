# 本地服务器导航页设计方案

0.1.2 的 [插件 Worker 执行模型](plugin-workers.md)：主线程负责回环入口、HTTP/WS 背压转发、线程监测及退出控制；任务管理器和系统优化分别声明独占 Worker，其他插件在默认共享 Worker 装配。任务管理器引擎只在所属 Worker 导入，目录、鉴权、凭据、指纹与连接额度通过异步宿主接口访问；计数来自协调端预留，不能用滞后快照放行新连接。其他跨插件调用使用 SDK 和 interop。共享线程阻塞仍影响同组业务，前端渲染及进程级故障不在此隔离保证内。

已实现 [公开控件与跨插件界面扩展](plugin-ui-extensions.md)：清单定义默认公开、可显式关闭的控件契约（插件 ID/局部 ID/版本/用途/字段说明），前端激活暂存注册后统一发布。菜单、标签页、面板、操作栏由 SDK 组件挂载并登记实例；查找仅返回公开描述，注入仅使用声明的内容接口。非公开控件不接受其他插件贡献；禁用 / 更新撤销旧代次，失效上下文不能继续调用。静态开发目录从清单生成，不运行插件代码，见 [扩展点表](plugin-ui-catalog.md)。普通 DOM 不自动注册或开放。

已实现首版 [MCP 工作台接入](mcp-implementation.md)：可选 automation 声明、独立 AI 身份、统一授权与操作记录、标准 stdio 连接器和内部 WS。AI SSH 由后端任务持有，现有工作区显示带 AI 标记的同一 PTY；默认人工只读，手动接管，任务结束自动收尾。原始方案保留在 [设计文档](mcp-workbench.md)，范围和验证以实施说明为准。

## 1. 状态与目标

本文保留产品与技术设计。当前已接入 Cordis / Hono / WS / SQLite、本机 SSH 导入、可选主密码的凭据保存、网页 SSH、内嵌 RDP / VNC、系统 RDP 启动与历史对话框；导航和管理页保存后可跨刷新及后端重启读取。实现契约见 [WS 协议](websocket-protocol.md)、[凭据](credentials.md)与 [管理页](management.md)。下文未标明已实现的扩展设计仍为目标。

项目面向单用户 Windows 桌面环境，作为浏览器主页运行在 `http://127.0.0.1:3030`。通过分组、搜索和收藏管理大量服务器，点击 SSH 打开网页终端，RDP / VNC 可在网页工作区显示桌面，RDP 也保留系统客户端入口。

目录、SSH、VNC 与系统 RDP 入口由一个 Node.js 进程提供。网页 RDP 由独立 Cordis 插件按会话启动随项目附带的 FreeRDP 辅助进程，无外部网关。配置与专用输出历史库使用 SQLite，前端构建后由后端提供静态资源。服务默认仅监听 IPv4 回环地址，不面向局域网或公网部署。

Windows 默认通过无主窗口托盘运行，轻量 supervisor 统一持有前后端服务进程；右键打开主页、按当前用户登录自启、重启与退出。开发、正式、前台调试与直接后端入口共用用户应用配置目录级单实例；更换数据目录、端口或仓库路径不另起服务。重复运行等待已有实例就绪并打开其实际主页；控制权在构建和数据库加载前取得。托盘采用系统自带 WinForms，不增加 Electron，详见[Windows 托盘](windows-tray.md)。

前后端业务通信全部走 WebSocket，统一承载请求响应、主动推送、认证、导入导出和终端数据。HTTP 只提供页面、静态资源与 WS 升级握手，不维护 REST 业务接口。

## 2. 产品范围

[系统优化官方内置独立插件](system-optimizer.md)首版位于 `plugins/system-optimizer/`，目标为本机 Windows 11 x64。开发/生产启动通用扫描随附 `plugins/`，发行包包含同目录；首次兼容包自动安装，禁用和卸载意图保留。使用已实现的[公共 SDK](plugin-sdk.md)注册左侧工具和右侧工作区，业务未加入宿主按钮、服务或 RPC 分支。提供启动登记、10 项用户设置、应用、系统存储入口及恢复记录；固定助手通过 stdin 接收结构化动作，原值由 DPAPI 加密持久保存后才写入，读回核对，恢复检查冲突。管理员动作、直接文件清理及其他平台仍待适配；真实环境仅完成只读与 DPAPI 验证。

已实现[任务管理器插件](task-manager.md)：`service:taskManager` Cordis 服务、`task-manager` 前端槽位、Go 原生采集器，管理本机及已保存的 SSH 目标。三平台安装路径统一为用户目录 `.webnav/tools/task-manager`；缺少采集器时点击自动通过 SFTP 上传校验，以独立 SSH exec 的 stdio 采集，不开放远端端口。0.2 的可选性能快照增加真实逐核计数、物理磁盘吞吐、GPU/专用显存/共享内存；前端提供性能切换与占用热度，设备历史有界，权限或驱动缺失保持未知。远程监控纳入八连接预算，页面关闭/锁定回收；活动安装和采集阻止提供者切换与整包更新。具体平台验收、当前能力和未实施的高级设计见专门文档。

0.3 将即时查看与显式持续记录拆开：页面/SSH 生命周期只持有前台 stdio 查看桥接；目标的独立记录器持有本用户单实例锁，写入版本无关的 `recording-v1` 分段压缩记录与索引。后台不持有 SSH 凭据、不开放端口、不随 WebNav 退出停止；仅设置写入可以明确启停。查询通过重新建立的已鉴权桥接，固定时间范围、最多 300 个代表点及按需单点详情；历史身份不能直接进入活跃进程动作。配置、期望版本、持久操作 ID、运行心跳和记录文件各有明确职责，状态区分启用意图与实际运行。

任务管理器的表格列宽由前端指令独立管理，按表标识保存浏览器外观偏好；与采集数据、连接生命周期和插件配置分离。指令拥有拖动捕获、尺寸观察及监听器清理，卸载释放；页面各视图共享语义色变量，标题色带与卡片正文保持明显反差。

进程选中、输入框展示与实际筛选分别管理；固定布局只保留一份有界行集合，最新快照按 PID + 启动时间更新数值，缺失行不冒充实时指标。菜单复用前端上下文菜单组件并绑定监控 ID，进程退出或目标变化清除；复制和显式在线搜索在浏览器处理，详情及结束仍走既有业务 WS 和确认计划。

多选观察与单行焦点独立：最多 200 个稳定进程身份，按勾选顺序显示，CPU/内存各最多 300 点、5 分钟，卡片分页渲染；缺失或 PID 复用产生断点。批量结束复用逐项确认计划，最多 16 项，明确确认后顺序执行，失败或未知立即停止后续项。0.3.1 的启动参数采用独立只读 `taskManager.commandLine`，原生查询前后复核创建身份；结果不进入快照、历史或公开插件扩展上下文，页面只保留当前单选结果并丢弃迟到响应。断线、锁定、目标切换释放观察数据与参数文本。

- 首页：紧凑服务器列表、分组树、收藏、最近使用及全文本搜索入口。
- 网页收藏：标题下方固定宽度的网页截图卡片，独立名称和网址，点击打开新标签。账密由现有凭据服务保存，有主密码时每次查看单独验证；截图按需通过独立 Edge/Chrome 生成并缓存，详见[网页收藏](web-bookmarks.md)。
- 分组：支持父子层级、排序和调整归属；首版每台服务器只有一个所属分组，可带多个标签。
- 搜索：匹配服务器名称、地址、标签、备注及连接名称，提供 `Ctrl+K` 快捷入口。
- 服务器行：展示别名与默认地址，直接提供 SSH、RDP、网页等多个入口。
- 管理页：编辑服务器、分组、连接入口和凭据引用，支持批量导入、导出及导入预览。
- 终端工作区：默认占满右侧正文，左侧导航与顶部搜索、设置保留，顶部中间以可压缩标签管理 SSH 会话。支持将多个终端分别悬浮、拖动、缩放和收回；切换目录、标签或悬浮形式复用原连接与 xterm 实例，详见[界面设计](ui-design.md#终端工作区)。
- 实时终端：每会话默认保留最近 2,000 行历史，最旧内容自动淘汰；向上翻阅不强制跳底，提供“有新输出 / 回到最新”入口。
- 终端配色：方案定义由 `terminal-themes` 服务保存，SSH / 本地终端入口通过目录中的 `terminalThemeId` 独立选择；终端右键配色绑定当前服务器及连接入口，管理方案另行进入。保存选择只更新目录引用，运行终端响应配色变化，不重建连接或清理输出。
- 输出历史：后端默认保存 SSH 输出的纯文本，连接级可关闭。“查看历史”打开独立只读对话框，可选择会话、搜索和分页；打开时固定已保存文本的范围，手动刷新才纳入新输出，不实时追加、不向活动终端补历史。

服务器与连接入口分开建模。例如“开发工作站”维护一份机器资料，下面挂载 `SSH / developer`、`RDP / Administrator` 和 `Jenkins` 三个连接。

## 3. 技术选型

| 层次 | 方案 | 职责 |
| --- | --- | --- |
| 运行时 | Node.js LTS、TypeScript | 本地常驻进程与类型约束 |
| 后端组织 | Cordis | 服务依赖、插件装配与生命周期 |
| 页面与握手 | Hono、Node adapter | 页面、静态资源、WS 升级 |
| 业务通信 | 浏览器原生 WebSocket、后端 ws | RPC、主题订阅、独立终端通道 |
| 前端 | Vue 3、Vite、TypeScript | 导航、管理及终端工作区 |
| 数据存储 | SQLite、better-sqlite3 | 配置、迁移、收藏、历史与指纹 |
| SSH | xterm.js、ssh2 | 网页终端显示与真实 SSH 连接 |
| RDP | Windows mstsc.exe | 启动本机远程桌面客户端 |
| 网页 RDP | FreeRDP Cordis 插件、原生辅助进程、Guacamole JS 显示编解码 | 后端交接认证，在现有工作区显示桌面 |
| 网页 VNC | noVNC、Node TCP / RFB 认证桥 | 后端认证并转发，浏览器渲染及输入 |

项目采用 pnpm 工作区，TypeScript 开启严格类型并使用 ESM。实施时选择相互兼容的稳定版本并写入统一锁文件，尤其验证 Cordis 的服务注册、依赖声明和资源释放 API。端口 `3030` 是默认设计值，可通过配置调整；占用时应明确报错，避免静默启动到未知地址。

```text
webnav/
├── AGENTS.md                # 仓库协作与实现约定
├── README.md                # 项目说明、实际进度与使用入口
├── docs/
│   ├── architecture.md      # 本文：产品与架构方案
│   ├── management.md        # 当前管理页操作与 JSON 格式
│   ├── websocket-protocol.md # WS 消息、鉴权、订阅与重连约定
│   ├── terminal-performance.md # 实时终端历史淘汰、输出预算与滚动行为
│   └── terminal-history.md  # 后端文本留存、固定范围查询与搜索分页
├── backend/                 # Node.js / TypeScript / Cordis 后端
└── frontend/                # Vue / Vite 前端
```

后续后端代码建议按 `src/core/`、`src/plugins/`、`src/contracts/` 和 `src/migrations/` 组织，通用服务接口放在 `core/`，具体服务实现由插件提供；前端按 `src/views/`、`src/components/`、`src/connectors/` 与 `src/transport/` 组织。这些是规划目录，按实际实现建立。

运行数据放在用户可写的数据目录，例如 `%LOCALAPPDATA%/WebNav/`，不写入源码目录。配置数据库与专用输出历史库分开，历史库限制为当前本机用户访问。数据库、输出历史、凭据、私钥、临时 RDP 文件和运行日志不得提交 Git。安装位置与数据位置分离，以便升级和备份。

## 5. Cordis 服务与插件边界

[插件总览与配置页](plugin-settings.md)首版已实现：默认已安装、可选声明式或自定义配置、同一设置实例、停用配置、命名字体。实际接口见 [SDK](plugin-sdk.md)。

目标设计扩展为[通用插件平台与插件间通信](plugin-platform.md)：保留装配、身份/凭据、存储基础设施、WS 和资源管理等必需内核，业务功能通过公共扩展点提供；插件可定义有版本的公开服务、状态事件和依赖，无需逐个扩充宿主业务白名单。现有内置模块逐步迁移，通用页面与后端服务/状态通信已实现首版。

更新预览绑定具体提交及插件配置 revision，详情区分已安装和正在运行版本；具体行为见 [插件系统](plugins.md)。正式版由独立单实例 supervisor 管理整包在线更新：签名清单、版本目录、稳定入口、任务收尾、精确就绪校验和失败恢复；源码模式不覆盖自身。Gitee 源读取普通发行版页面并缓存、退避。实现与发布边界见 [在线更新](online-updates.md)，依据见 [Harness 调研](harness-updates-research.md)。

宿主负责通用配置、装配、生命周期和工作区承载。新工具通过 contributes/registerTool 注册，设置与字体共享注册表，后端 interop 通过版本契约调用和完整状态快照协作。任务管理器入口及配置同步/MCP 设置已迁移；历史内置服务仍由 app.ts 装配，固定槽作为兼容层保留。独立工具无需增加宿主业务分支；当前边界见[实施记录](plugin-platform-implementation.md)。

连接器注册协议包含类型标识、显示名称、配置校验器、支持的动作及启动处理器。SSH 与网页桌面返回会话标识，系统 RDP 返回客户端启动结果，网页入口返回经过协议校验的 URL。具体 TypeScript 接口在实施时确定。

领域服务不接触原始 socket。RPC 方法注册与主题发布通过 `rpc`、`subscriptions` 服务完成；绑定层在数据库提交成功后发布公开数据变更，内部事件和凭据不会直接广播。前端统一封装 RPC 调用与订阅；具体协议见 [WebSocket 通信协议](websocket-protocol.md)。

插件的定时器、事件监听、RPC 处理器、订阅、WebSocket、SSH 连接和注册项必须绑定 Cordis 生命周期，在 `dispose` 阶段取消或关闭。退出时先停止接收请求，再结束 SSH 会话和释放数据资源。

前端通过显式注册表映射连接类型、配置表单和展示组件，第三方浏览器 ES module 使用宿主 Vue 与 SDK 注册视图。插件管理器支持 Git 安装、平台校验、固定分类、持久市场缓存和可替换的服务提供者。内置元数据位于 `backend/plugins/`，默认市场为 Gitee 公开索引。启停、升级与替换默认在线生效：稳定服务桥保留消费端及订阅，独立 Cordis 生命周期暂存新注册，验证后切换并清理旧实例；活动连接和资源租约阻止提前卸载，资源结束后自动切换。前端订阅插件变化，仅替换变化的组件、样式与注册。无法在线替换或旧资源清理失败时明确待重启。详见 [插件系统](plugins.md)。未启用的类型可保留配置，但显示为不可启动。

## 6. 数据模型

持久对象使用字符串 ID；时间统一存储为 UTC，界面按用户时区展示。端口、协议选项和 URL 使用对应连接器的 schema 校验。

以下是后端持久化模型设计。当前实现将连接数组嵌在服务器对象内，网页地址直接使用 `url`，SSH 使用 `saveHistory` 保存新会话生效的历史开关；暂不包含凭据引用、排序或时间字段。原型 JSON 格式与校验边界见 [管理页说明](management.md)，数据库当前以带版本的目录文档保存，凭据与主机指纹另表管理；下表为后续进一步拆分的数据模型。

| 实体 | 主要字段 | 约束 |
| --- | --- | --- |
| `Group` | `id`、`name`、`parentId`、`sortOrder` | 不允许父子循环；删除前明确下属记录的归属 |
| `Server` | `id`、`name`、`host`、`groupId`、`tags`、`note`、`favorite`、`sortOrder` | `groupId` 可空，表示未分组 |
| `Connection` | `id`、`serverId`、`name`、`type`、`port`、`username`、`credentialRefId`、`options`、`sortOrder` | 默认使用服务器地址，按协议存储必要选项；网页 URL 放入 `options` |
| `CredentialRef` | `id`、`name`、`kind`、`provider`、`reference` | 保存引用与元数据，不保存明文密码或私钥内容 |
| `KnownHost` | `id`、`host`、`port`、`keyAlgorithm`、`fingerprint`、`approvedAt` | 按实际连接端点校验，算法升级与指纹变更均需明确处理 |
| `RecentConnection` | `connectionId`、`lastUsedAt` | 记录用户发起连接的时间，不作为连接成功证明 |

所有持久对象按需要包含 `createdAt`、`updatedAt`。活动 SSH 会话单独保存在内存，包含会话 ID、连接 ID、拥有者、状态、创建时间和关闭原因；后端重启不恢复远端 Shell。

专用历史库另存会话元信息和有序文本记录，支持按会话与固定范围查询；不双存原始 ANSI 字节录像。已提交的文本在保留期内可跨页面刷新和服务重启读取，关闭 Shell 不立即删除记录。默认保留 7 天、单会话 100 MiB、全局 1 GiB，额度按保存文本 payload 计量，实际数据库文件、索引和 WAL 另有空间保护；这些均为待验证设计初值。详细字段、冻结查询范围和清理语义见 [SSH 输出历史设计](terminal-history.md)。

SQLite 开启外键约束，迁移按版本执行。配置写入使用事务，删除服务器时明确处理其连接和历史；共享凭据引用不随服务器删除。目录变更采用版本字段或等价机制避免管理页覆盖并发编辑。

## 7. 纯 WebSocket 业务通信

浏览器自动填写使用独立 `browserExtension` Cordis 服务及 `/ws/extension` 通道，按浏览器配置文件配对、双向认证、加密消息并逐网站授权。扩展也可由用户点击读取当前网页和已输入账密，经弹窗确认后调用 `webBookmarks` 保存或更新收藏，复用凭据事务、版本校验、截图队列和首页订阅。它不复用普通网页 Cookie，不访问连接凭据；主密码锁定即停止取密和保存，并清除保存预览。HTTP/HTTPS 共用域名匹配，非默认端口区分。扩展源码在 `extension/`，完整契约见[浏览器自动填写](browser-extension.md)。

远程编辑器的生命周期操作也走业务 WS。它自带的网页资源与协议经独立回环 HTTP / WS 代理和 SSH 通道传输；这属于第三方编辑器工作台，不向 WebNav 增加 REST 业务接口，详见[远程编辑器](remote-editor.md)。
每个浏览器页面建立一个 `/ws` 业务通道，以带版本、请求 ID 的 JSON 消息执行 RPC，并订阅配置和会话状态。前端只需要调用业务方法和订阅状态，不轮询目录。RPC 包含明确的成功或错误响应；主动推送是独立事件消息。

每个 SSH 会话另建 `/ws/terminal` 通道，绑定已授权的会话后传输二进制终端字节流。独立通道隔离业务消息和高频终端输出的发送队列，各自设置流量和缓冲上限。

独立历史对话框通过业务 WS RPC 获取会话列表、固定已保存文本的查询范围、搜索和分页。查询结果不订阅实时追加；用户手动刷新才重新固定范围，前端始终只保留有界页缓存。历史查询与活动终端的字节流、ACK 和背压相互独立。

数据订阅返回一致快照和版本号，之后推送已提交变更。重连重新认证并重建订阅；首版重新获取快照，不提供离线事件回放。超时或断线不能证明操作失败，有副作用的请求不得自动重放。

导入文件内容经 WS 提交，导出的 JSON 与 `.rdp` 文本经 WS 返回，浏览器创建 Blob 下载。认证、协议格式、业务方法、幂等边界、快照一致性和终端流量控制统一定义在 [WebSocket 通信协议](websocket-protocol.md)。当前可调用方法与简化实现以 WS 协议文档为准。

当前管理页通过 WS 完成导入预览、带版本的事务替换与导出。后端提交后向订阅者推送完整目录快照。

## 8. SSH 会话生命周期

链路为 `xterm.js ↔ WebSocket ↔ 本地 Node.js / ssh2 ↔ SSH 服务器`。浏览器只承担显示与输入，SSH 协议、凭据使用和主机校验由后端完成。

1. 用户经业务 WS 调用 `connections.open`，后端校验配置与权限，返回待连接会话及短时一次性终端绑定票据。终端 WS 绑定时校验身份、票据和归属；未及时绑定的会话超时回收，绑定后启动 SSH 握手。
2. 建立 SSH 传输时检查主机指纹；首次连接展示实际指纹等待确认，确认前不完成用户认证。
3. 已记录指纹不匹配时阻止连接，用户核实后通过明确操作更新记录，不能自动接受。
4. 使用会话临时密码、私钥或后续支持的系统凭据完成认证，创建带终端尺寸的 PTY/Shell。
5. 双向传递数据；窗口变化同步远端尺寸。单页内切换视图时由全局会话状态保留连接。
6. 用户明确关闭终端、远端退出或 SSH 链路失败后，释放 Shell、SSH 客户端、该终端 WebSocket 和内存会话；浏览器显示通道断开只移除视图，业务通道仍可继续工作。

业务 WS 暂时断开时，已经绑定且健康的终端 WS 可继续工作；暂停需要业务通道的操作，重连后重新同步状态。后端持有普通 SSH / 本地终端、有限 headless 屏幕和布局，终端 WS 断开只脱离视图；刷新和关闭浏览器再打开，经新票据接回原 Shell。远端断线或后端重启仍结束会话，历史库不能复活 Shell。桌面/设备按显式 viewer 能力同样保留后端连接，完整边界见[后台会话](persistent-sessions.md)。

实时终端的历史容量与可见区渲染交给 xterm.js；应用不为每行实时输出创建 Vue 节点或保存全量输出副本。历史淘汰只处理已经解析的旧行，未解析输出由累计 ACK、有限窗口和背压控制，避免损坏终端状态。未选中的终端继续有限解析，释放时销毁实例及 addons。详见 [终端历史淘汰与持续输出控制](terminal-performance.md)。

后端接收 SSH 输出后，通过 `terminal-history` 服务进行有界跨块解析，保存可搜索的纯文本；首版不把文本转录当作 `vim`、`top` 等 TUI 的屏幕录像。持久化队列与查询均需限额，写入失败或清理导致缺失时明确提示，不能无界积压。已实现的独立只读历史对话框使用有界分页显示文本，关闭对话框不影响活动 SSH；查看旧记录不会重新建立远端连接。

## 9. 网页桌面与系统 RDP

网页 RDP / VNC 使用独立 `/ws/desktop`，通过后端保存的入口建立远端连接。前端按需加载 Guacamole / noVNC 视图，共用标签页和悬浮容器，复用画布提供有界缩略图；凭据、显示、流控和验证边界见[网页桌面](embedded-desktops.md)。下面的 mstsc 语义只适用于选择系统客户端的 RDP 入口。

网页 RDP 未配置 `rdpDisplay` 时使用固定 1920 × 1080，已配置的入口继续采用其保存值；网页上限为 4096 × 2160。仅显式全屏模式通过 Display Control 请求跟随网页尺寸，工具栏全屏仍需要浏览器用户手势。

FreeRDP 开启 GFX / H.264 协商，并通过 Windows Media Foundation 解码受支持的远端视频流；本机输出仍是 JPEG / PNG 图片，不是 H.264 直传浏览器。大面积运动使用 JPEG，小变化按实际矩形使用 PNG，静止 250 ms 后补一帧无损精修；大于 720p 的变化范围由四个常驻编码线程处理同一锁定画面。当前刷新中全部区域发出后以一个 `sync` 提交，网页完成解码和绘制后才确认。最多两帧在途以重叠编码与呈现，后续变化合并到当前像素缓冲，不排队旧截图。输入和 ACK 通过事件唤醒；Node 按单张图片聚合指令，原生记录按长度一次分配并增量复制，避免大图片反复拼接。

桌面工具栏的 FPS 统计最近一秒完成网页绘制的更新，静止时可以为 0。悬停信息区分远端更新 / GFX 帧率、本机桥接处理和网页呈现耗时；这些时间不包含完整网络与输入延迟。模拟组件吞吐与真实网页、真实远端性能分别验证，详见[刷新性能对比](embedded-desktops.md#刷新性能对比)。

本地后端必须运行在当前登录的 Windows 桌面用户上下文，才能向用户展示 mstsc 窗口。托盘自启采用用户登录后启动方式；作为无交互系统服务运行不在首版范围。

启动 RPC 只接收已保存的连接 ID，后端解析受 schema 约束的配置，用固定的可执行文件与参数数组启动 `mstsc.exe`，不拼接 shell 命令，也不接受任意命令行参数。需要的 `.rdp` 文件采用受控字段生成，拒绝换行注入并及时清理。下载时通过 WS 返回文本供浏览器生成文件。

成功结果表示“远程桌面客户端已启动”，不代表远端认证或连接成功。编辑 RDP 入口可直接保存密码，与目录修改在一个事务内提交，凭据仍单独存储并遵守用户选择的保存方式。连接时通过固定的本机程序向 Windows 当前登录会话交接凭据，再启动 mstsc；密码不进入命令行或 `.rdp` 文件。临时 RDP 文件传递地址、可选用户名与显示设置，定时清理，详见[凭据交接](credentials.md#windows-rdp-凭据交接)。网页或本地导航服务关闭时不结束已启动的 mstsc 窗口。`.rdp` 下载仍为后续功能。

每个 RDP 入口通过可选 `rdpDisplay` 保存窗口固定分辨率、单屏全屏或全部显示器全屏；系统客户端省略时保持其默认行为，网页省略时为固定 1080p。系统模式窗口宽高均为 200–8192 整数，全屏模式不接受宽高；共享校验覆盖编辑、WS 保存与导入。配置随目录持久化和导出，启动时根据已保存的入口生成显示属性，未填写用户名也生效，不修改其他入口或全局客户端配置。详见[管理页显示设置](management.md#rdp-显示设置)。

## 10. 本地访问与配置保护

- 获取页面时 HTTP 响应自动建立高熵的本机会话 Cookie，使用 `HttpOnly`、`SameSite=Strict` 和有效期，页面响应禁用缓存。已有有效 Cookie 不重复覆盖；开发页面由 Vite 页面中间件透传后端建立的 Cookie。
- 不使用配对码或人工浏览器授权。后端启动后，页面自动建立业务 WS、读取全局状态并加载目录；只有设置主密码且未解锁时才要求输入。
- 校验 HTTP `Host` 及每个 WS 升级的精确 `Origin`，拒绝未允许或缺失的来源。终端通道升级须具有有效本机会话，绑定时再次校验归属。会话失效后页面自动重建会话，不重新引入人工步骤。
- 开发模式可以直接打开 Vite 地址，页面中间件自动向后端建立本机会话，前端来源单独配置；业务连接中断后重新连接并获取目录快照，具体规则见 WS 协议。生产环境不开放通配 CORS；回环监听本身不代替身份与来源校验。
- 密码和私钥口令可持久保存，默认可逆编码；右上角全局设置可启用主密码，统一迁移已有秘密。访问页面先检查解锁状态，有效期按分钟配置，可选分钟、小时、天或服务运行期间永不过期，后端统一计时并推送锁定，见 [凭据保存](credentials.md)。
- 私钥引用本地文件；普通 RPC 不回传私钥内容。私钥口令由凭据服务保存。
- 终端输出、密码、私钥和完整凭据不得写入常规日志；错误只保留排障所需的脱敏信息。
- 专用历史库默认记录 SSH 输出，可按连接关闭；不主动记录终端输入或认证数据。远端回显仍可能包含秘密，不能承诺自动完整脱敏；历史仅通过已鉴权查询返回，不向浏览器持久存储写入，不混入普通配置备份。
- 网页入口仅允许明确支持的 `http:` / `https:` 协议，禁止通过配置执行任意脚本。

JSON 导出包含 `schemaVersion`、目录和非秘密的连接配置；不包含密码、私钥、浏览器会话、主机信任记录或输出历史，凭据引用恢复后需重新绑定。CSV 首版只用于目录与基础连接字段导入。

导入必须经过大小限制、schema 校验、引用完整性检查及新增/覆盖预览；应用时验证预览未过期且目录版本未变化，在一个事务内完成。失败不留下部分更新，未知连接类型应提示并保持不可启动。数据库备份与可分享的配置导出是不同能力，备份文件仍应妥善保护。

## 11. 实施阶段与验收

| 阶段 | 交付范围 | 验收重点 |
| --- | --- | --- |
| 1：导航与管理 | Cordis 骨架、WS RPC/订阅、持久化、分组、标签、搜索、收藏、最近使用、多入口、管理与导入导出 | 数百台示例服务器可流畅查找；配置推送和重连快照一致；重启配置不丢；导入失败原子回滚 |
| 2：连接能力 | 网页 SSH、多会话、有限实时历史与输出流控、后端文本留存与独立历史查询、凭据处理、主机指纹、RDP 启动与网页入口 | 交互及尺寸同步；持续输出时历史和队列有界、可翻阅；历史范围固定、跨页搜索、手动刷新、清理提示与跨重启查询；指纹变化阻断；断开资源释放；RDP 状态准确 |
| 3：日常完善 | Windows 登录后自启、备份恢复、快捷键、故障提示与打包 | 单进程提供构建页面；自启与端口冲突行为明确；备份可恢复；收藏夹中的连接快速打开 |

实现时对导入事务、来源鉴权、主机指纹、会话清理、进程参数、RPC 去重、订阅一致性与慢终端流量控制进行有意义的自动验证，优先使用测试服务与模拟连接器；真实 SSH 与 Windows RDP 的集成验收仅使用当前任务明确授权的目标。只有实际具备启动入口和完成验证后，才在 README 中提供可执行的运行命令。

跳板机、团队共享及跨设备会话恢复延期。[内置配置同步](config-sync.md)已实现加密便携快照、GitHub / Gitee 传输适配、三方冲突、历史恢复、账号密码更换与可选自动同步；真实云端仓库尚未验收。插件已支持公开 Git 安装、热插拔与热更新，不能在线切换时提示待重启，纯主题下载后立即可用。热更新需要插件遵守资源租约与清理契约，不承诺任意第三方代码可安全卸载。网页 RDP / VNC 的本机模拟测试不能代替真实远端兼容与容量验收；详见网页桌面文档中的验证记录。

### 终端工作区与配色

前端以主标签管理会话组，用二叉布局树支持任意 SSH 窗格继续上下 / 左右分屏。布局树计算平面矩形，终端视图保持同层稳定实例，Vue Teleport 用于独立显示；窗口调整只修改 PTY 行列，不缩放字号。关闭窗格释放单个会话、合并剩余布局，关闭主标签释放整组；悬浮与独立显示成员保留组归属。独立显示页的视图依赖原主页，主页关闭时回收显示窗口，后端连接继续保留。terminal-themes Cordis 服务持久化主题并按明确订阅推送完整版本快照。详见 [终端工作区](terminal-workspace.md)。
