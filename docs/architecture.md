# 本地服务器导航页设计方案

## 1. 状态与目标

本文是待实现的产品与技术设计。当前仓库仅初始化文档与前后端目录骨架；本文中的插件、RPC 方法、命令及行为均不代表已实现，也不承诺具体依赖版本。

项目面向单用户 Windows 桌面环境，作为浏览器主页运行在 `http://127.0.0.1:3030`。通过分组、搜索和收藏管理大量服务器，点击 SSH 打开网页终端，点击 RDP 启动本机远程桌面。

首版正式运行只需要一个 Node.js 进程和一个 SQLite 数据库。前端构建后由后端提供静态资源；开发阶段可以分别运行前后端。服务默认仅监听 IPv4 回环地址，不面向局域网或公网部署。

前后端业务通信全部走 WebSocket，统一承载请求响应、主动推送、认证、导入导出和终端数据。HTTP 只提供页面、静态资源与 WS 升级握手，不维护 REST 业务接口。

## 2. 产品范围

- 首页：紧凑服务器列表、分组树、收藏、最近使用及全文本搜索入口。
- 分组：支持父子层级、排序和调整归属；首版每台服务器只有一个所属分组，可带多个标签。
- 搜索：匹配服务器名称、地址、标签、备注及连接名称，提供 `Ctrl+K` 快捷入口。
- 服务器行：展示别名与默认地址，直接提供 SSH、RDP、网页等多个入口。
- 管理页：编辑服务器、分组、连接入口和凭据引用，支持批量导入、导出及导入预览。
- 终端工作区：以标签管理多个独立 SSH 会话，切换首页或终端标签时保留活动连接。
- 终端历史：每会话默认保留最近 2,000 行历史，最旧内容自动淘汰；向上翻阅不强制跳底，提供“有新输出 / 回到最新”入口。

服务器与连接入口分开建模。例如“开发工作站”维护一份机器资料，下面挂载 `SSH / developer`、`RDP / Administrator` 和 `Jenkins` 三个连接。

## 3. 技术选型

| 层次 | 方案 | 职责 |
| --- | --- | --- |
| 运行时 | Node.js LTS、TypeScript | 本地常驻进程与类型约束 |
| 后端组织 | Cordis | 服务依赖、插件装配与生命周期 |
| 页面与握手 | Hono、Node adapter | 页面、静态资源、WS 升级 |
| 业务通信 | 浏览器原生 WebSocket、后端 ws | RPC、主题订阅、独立终端通道 |
| 前端 | Vue 3、Vite、TypeScript | 导航、管理及终端工作区 |
| 数据存储 | SQLite、better-sqlite3 | 配置、迁移、收藏、历史与指纹 |
| SSH | xterm.js、ssh2 | 网页终端显示与真实 SSH 连接 |
| RDP | Windows mstsc.exe | 启动本机远程桌面客户端 |

项目采用 pnpm 工作区，TypeScript 开启严格类型并使用 ESM。实施时选择相互兼容的稳定版本并写入统一锁文件，尤其验证 Cordis 的服务注册、依赖声明和资源释放 API。端口 `3030` 是默认设计值，可通过配置调整；占用时应明确报错，避免静默启动到未知地址。

## 4. 仓库与部署结构

```text
webnav/
├── AGENTS.md                # 仓库协作与实现约定
├── README.md                # 项目说明、实际进度与使用入口
├── docs/
│   ├── architecture.md      # 本文：产品与架构方案
│   ├── websocket-protocol.md # WS 消息、鉴权、订阅与重连约定
│   └── terminal-performance.md # 历史淘汰、输出预算与滚动行为
├── backend/                 # Node.js / TypeScript / Cordis 后端
└── frontend/                # Vue / Vite 前端
```

后续后端代码建议按 `src/core/`、`src/plugins/`、`src/contracts/` 和 `src/migrations/` 组织，通用服务接口放在 `core/`，具体服务实现由插件提供；前端按 `src/views/`、`src/components/`、`src/connectors/` 与 `src/transport/` 组织。这些是规划目录，按实际实现建立。

运行数据放在用户可写的数据目录，例如 `%LOCALAPPDATA%/WebNav/`，不写入源码目录。数据库、凭据、私钥、临时 RDP 文件和运行日志不得提交 Git。安装位置与数据位置分离，以便升级和备份。

## 5. Cordis 服务与插件边界

核心只负责配置加载、插件装配及生命周期。插件通过显式注入的服务协作，避免直接引用其他插件的内部对象。

| 内置插件 | 暴露的服务或能力 | 主要依赖 |
| --- | --- | --- |
| `storage` | 数据访问、迁移、事务与备份 | 配置 |
| `credentials` | 按引用解析凭据、会话临时凭据 | 配置；系统凭据适配器按需启用 |
| `connectors` | 连接器类型与启动能力注册 | 无 |
| `sessions` | 活动会话状态与资源归属 | 无；活动会话保存在内存 |
| `auth` | 未授权会话、一次性配对码、授权与过期检查 | 配置 |
| `http` | 页面入口、静态路由、WS 升级承载 | `auth` |
| `transport` | `rpc` 方法注册表、`subscriptions` 订阅服务、WS 连接和流量控制 | `http`、`auth` |
| `catalog` | 分组、服务器、连接、收藏、最近使用 | `storage`、`connectors` |
| `ssh` | SSH 连接器、终端会话及主机指纹校验 | `catalog`、`storage`、`credentials`、`sessions`、`connectors` |
| `rdp-local` | RDP 连接器、mstsc 启动及 RDP 文件生成 | `catalog`、`connectors` |
| `rpc-bindings` | 将领域服务绑定为已校验的 RPC 方法及公开订阅主题 | `rpc`、`subscriptions`、`auth`、`catalog`、`sessions`、`connectors` |
| `webui` | 提供前端静态资源 | `http` |

连接器注册协议包含类型标识、显示名称、配置校验器、支持的动作及启动处理器。SSH 返回会话标识，RDP 返回客户端启动结果，网页入口返回经过协议校验的 URL。具体 TypeScript 接口在实施时确定。

领域服务不接触原始 socket。RPC 方法注册与主题发布通过 `rpc`、`subscriptions` 服务完成；绑定层在数据库提交成功后发布公开数据变更，内部事件和凭据不会直接广播。前端统一封装 RPC 调用与订阅；具体协议见 [WebSocket 通信协议](websocket-protocol.md)。

插件的定时器、事件监听、RPC 处理器、订阅、WebSocket、SSH 连接和注册项必须绑定 Cordis 生命周期，在 `dispose` 阶段取消或关闭。退出时先停止接收请求，再结束 SSH 会话和释放数据资源。

前端使用独立的静态注册表映射连接类型到图标、配置表单和展示组件。首版前后端插件随应用固定打包，启停配置重启生效，不提供动态安装或热加载。未启用的类型可保留配置，但显示为不可启动。

## 6. 数据模型

持久对象使用字符串 ID；时间统一存储为 UTC，界面按用户时区展示。端口、协议选项和 URL 使用对应连接器的 schema 校验。

| 实体 | 主要字段 | 约束 |
| --- | --- | --- |
| `Group` | `id`、`name`、`parentId`、`sortOrder` | 不允许父子循环；删除前明确下属记录的归属 |
| `Server` | `id`、`name`、`host`、`groupId`、`tags`、`note`、`favorite`、`sortOrder` | `groupId` 可空，表示未分组 |
| `Connection` | `id`、`serverId`、`name`、`type`、`port`、`username`、`credentialRefId`、`options`、`sortOrder` | 默认使用服务器地址，按协议存储必要选项；网页 URL 放入 `options` |
| `CredentialRef` | `id`、`name`、`kind`、`provider`、`reference` | 保存引用与元数据，不保存明文密码或私钥内容 |
| `KnownHost` | `id`、`host`、`port`、`keyAlgorithm`、`fingerprint`、`approvedAt` | 按实际连接端点校验，算法升级与指纹变更均需明确处理 |
| `RecentConnection` | `connectionId`、`lastUsedAt` | 记录用户发起连接的时间，不作为连接成功证明 |

所有持久对象按需要包含 `createdAt`、`updatedAt`。活动 SSH 会话单独保存在内存，包含会话 ID、连接 ID、拥有者、状态、创建时间和关闭原因；后端重启不恢复远端 Shell。

SQLite 开启外键约束，迁移按版本执行。配置写入使用事务，删除服务器时明确处理其连接和历史；共享凭据引用不随服务器删除。目录变更采用版本字段或等价机制避免管理页覆盖并发编辑。

## 7. 纯 WebSocket 业务通信

每个浏览器页面建立一个 `/ws` 业务通道，以带版本、请求 ID 的 JSON 消息执行 RPC，并订阅配置和会话状态。前端只需要调用业务方法和订阅状态，不轮询目录。RPC 包含明确的成功或错误响应；主动推送是独立事件消息。

每个 SSH 会话另建 `/ws/terminal` 通道，绑定已授权的会话后传输二进制终端字节流。独立通道隔离业务消息和高频终端输出的发送队列，各自设置流量和缓冲上限。

数据订阅返回一致快照和版本号，之后推送已提交变更。重连重新认证并重建订阅；首版重新获取快照，不提供离线事件回放。超时或断线不能证明操作失败，有副作用的请求不得自动重放。

导入文件内容经 WS 提交，导出的 JSON 与 `.rdp` 文本经 WS 返回，浏览器创建 Blob 下载。认证、协议格式、业务方法、幂等边界、快照一致性和终端流量控制统一定义在 [WebSocket 通信协议](websocket-protocol.md)。以上为实施提案，尚无可调用服务。

## 8. SSH 会话生命周期

链路为 `xterm.js ↔ WebSocket ↔ 本地 Node.js / ssh2 ↔ SSH 服务器`。浏览器只承担显示与输入，SSH 协议、凭据使用和主机校验由后端完成。

1. 用户经业务 WS 调用 `connections.open`，后端校验配置与权限，返回待连接会话及短时一次性终端绑定票据。终端 WS 绑定时校验身份、票据和归属；未及时绑定的会话超时回收，绑定后启动 SSH 握手。
2. 建立 SSH 传输时检查主机指纹；首次连接展示实际指纹等待确认，确认前不完成用户认证。
3. 已记录指纹不匹配时阻止连接，用户核实后通过明确操作更新记录，不能自动接受。
4. 使用会话临时密码、私钥或后续支持的系统凭据完成认证，创建带终端尺寸的 PTY/Shell。
5. 双向传递数据；窗口变化同步远端尺寸。单页内切换视图时由全局会话状态保留连接。
6. 用户关闭终端、远端退出或终端链路失败后，释放 Shell、SSH 客户端、该终端 WebSocket 和内存会话；业务通道仍可继续工作。

业务 WS 暂时断开时，已经绑定且健康的终端 WS 可继续工作；暂停需要业务通道的操作，重连后重新同步状态。终端 WS 断开则关闭对应 SSH 连接，异常掉线由心跳与超时清理。刷新页面会断开该页的全部通道，不承诺恢复同一个 Shell；手动重连创建新会话。长任务可由用户在远端使用 `tmux` 等工具管理，首版不代管持久远端会话。

历史容量与可见区渲染交给 xterm.js；应用不为每行输出创建 Vue 节点或保存全量输出副本。历史淘汰只处理已经解析的旧行，未解析输出由累计 ACK、有限窗口和背压控制，避免损坏终端状态。未选中的终端继续有限解析，释放时销毁实例及 addons。详见 [终端历史淘汰与持续输出控制](terminal-performance.md)。

## 9. RDP 启动语义

本地后端必须运行在当前登录的 Windows 桌面用户上下文，才能向用户展示 mstsc 窗口。后续自启采用用户登录后启动方式；作为无交互系统服务运行不在首版范围。

启动 RPC 只接收已保存的连接 ID，后端解析受 schema 约束的配置，用固定的可执行文件与参数数组启动 `mstsc.exe`，不拼接 shell 命令，也不接受任意命令行参数。需要的 `.rdp` 文件采用受控字段生成，拒绝换行注入并及时清理。下载时通过 WS 返回文本供浏览器生成文件。

成功结果表示“远程桌面客户端已启动”，不代表远端认证或连接成功。远程登录交给 Windows 客户端处理；首版不把密码写入命令行或 `.rdp` 文件。网页或本地导航服务关闭时不结束已启动的 mstsc 窗口，同时提供 `.rdp` 下载作为备用入口。

## 10. 本地访问与配置保护

- 首次获取页面时，HTTP 响应设置高熵、未授权的会话 Cookie，使用 `HttpOnly`、`SameSite=Strict` 和有效期，页面响应禁用缓存。已有有效 Cookie 不重复覆盖。未授权 Cookie 仅用于关联配对过程，不允许访问业务数据。
- 首次启动在本机启动窗口显示短时有效的一次性配对码。业务 WS 建立后提交 `auth.pair`，成功后服务端将对应会话标记为已授权，不需要额外 HTTP 认证接口。配对尝试限时限速，成功后配对码立即失效；配对凭据、临时密码不得进入 URL。
- 校验 HTTP `Host` 及每个 WS 升级的精确 `Origin`，拒绝未允许或缺失的来源。未授权的业务通道仅允许受限认证握手；终端通道升级必须已经授权，绑定时再次校验归属。会话过期或撤销时关闭全部所属通道并清理 SSH 资源。
- 开发模式从后端页面入口建立 Cookie 后跳转至已配置的同主机 Vite 地址，前端来源单独配置。升级连续失败时停止有界重试并提示重新加载后端入口，具体规则见 WS 协议。生产环境不开放通配 CORS；回环监听本身不代替身份与来源校验。
- 临时密码仅在连接建立所需期间保存在内存。需要持久保存的秘密应使用 Windows 系统凭据库或受操作系统保护的存储；具体适配器在实施前验证。
- 私钥可引用本地文件；普通 RPC 不回传私钥内容。私钥口令按临时凭据或系统凭据处理。
- 终端输出、密码、私钥和完整凭据不得写入常规日志；错误只保留排障所需的脱敏信息。
- 网页入口仅允许明确支持的 `http:` / `https:` 协议，禁止通过配置执行任意脚本。

JSON 导出包含 `schemaVersion`、目录和非秘密的连接配置；不包含密码、私钥、浏览器会话或主机信任记录，凭据引用恢复后需重新绑定。CSV 首版只用于目录与基础连接字段导入。

导入必须经过大小限制、schema 校验、引用完整性检查及新增/覆盖预览；应用时验证预览未过期且目录版本未变化，在一个事务内完成。失败不留下部分更新，未知连接类型应提示并保持不可启动。数据库备份与可分享的配置导出是不同能力，备份文件仍应妥善保护。

## 11. 实施阶段与验收

| 阶段 | 交付范围 | 验收重点 |
| --- | --- | --- |
| 1：导航与管理 | Cordis 骨架、WS RPC/订阅、持久化、分组、标签、搜索、收藏、最近使用、多入口、管理与导入导出 | 数百台示例服务器可流畅查找；配置推送和重连快照一致；重启配置不丢；导入失败原子回滚 |
| 2：连接能力 | 网页 SSH、多会话、有限历史与输出流控、凭据处理、主机指纹、RDP 启动与网页入口 | 交互及尺寸同步；持续输出时历史和队列有界、可翻阅；指纹变化阻断；断开资源释放；RDP 状态准确 |
| 3：日常完善 | Windows 登录后自启、备份恢复、快捷键、故障提示与打包 | 单进程提供构建页面；自启与端口冲突行为明确；备份可恢复；常用连接快速打开 |

实现时对导入事务、来源鉴权、主机指纹、会话清理、进程参数、RPC 去重、订阅一致性与慢终端流量控制进行有意义的自动验证，优先使用测试服务与模拟连接器；真实 SSH 与 Windows RDP 的集成验收仅使用当前任务明确授权的目标。只有实际具备启动入口和完成验证后，才在 README 中提供可执行的运行命令。

跳板机、SFTP、浏览器内 RDP、团队共享、云同步、动态插件安装及跨设备会话恢复延期。网页 RDP 可通过后续 Guacamole 连接器扩展，但需要 `guacd` 等额外部署组件。
