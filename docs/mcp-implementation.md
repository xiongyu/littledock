# MCP 工作台接入

2026-10-27 首版实现。原始设计保留在 [MCP 工作台方案](mcp-workbench.md)；本文说明当前可用范围及实际验证。

## 使用

更新代码后运行 `pnpm install`、`pnpm build`，从托盘重启工作台。进入 **全局设置 → AI 接入**，或在插件中心打开 **MCP 工作台接入 → 管理 AI 接入**。

1. 新建或编辑授权模板，选择能力和具体 SSH 入口。多个 AI 可以共用模板，修改模板立即影响其后续调用。
2. 填写 AI 名称并选择模板，点击“生成 MCP 配置”。默认模板仅允许读取目录和能力，不允许执行命令。
3. 将生成的配置加入支持本机 **stdio MCP** 的客户端。首次启动须在五分钟内完成配对；配对码仅能使用一次，后续使用本机保存的独立密钥。
4. AI 读取目标的 `serverId + connectionId` 后开始工作。执行/修改工具先返回具体预览、`operationId` 和 `ticket`，再调用 `workbench_apply`。同一已接受操作不会重复执行；结果未知时查询 `operation_status`。

配置使用当前 Node 可执行文件和项目内连接器的绝对路径。生产构建入口为 `backend/dist/mcp-bridge.js`，开发模式为 `backend/src/mcp-bridge.ts`。设置页自动生成正确地址和路径，包括开发前端与后端端口不同的情况。移动项目、Node 路径或数据目录后应重新生成配置。无需模型 API Key，也无需给每个 AI 分别配置服务器凭据或业务插件。

“撤销”单个 AI 或关闭 MCP 接入，立即阻止后续调用并回收其活动连接。设置主密码后，必须先在工作台解锁；AI 无法自行解锁、查看认证密码或接受主机指纹。

## 可用能力

| 来源 | 当前工具 |
| --- | --- |
| 宿主 | `catalog_list`、`plugins_list`、`workbench_apply`、`operation_status`、`task_status`、`task_finish` |
| SSH 终端 | `ssh_open`、`ssh_input` |
| SSH 系统信息 | `system_read`，固定只读探测命令 |
| SSH 文件管理 | `files_list`、`files_read`、`files_save`，仅限已存在普通文本文件 |
| 输出历史 | `history_list`、`history_read`，当前 AI 自己创建的任务，按当前目标授权重新检查 |
| 终端配色、网页收藏 | `themes_list`、`bookmarks_list`，不返回账号密码 |

文件工具使用独立 SFTP 通道，最多读取/修改 128 KiB 文本，分页最多 200 项。授权路径使用远端绝对路径；检查远端规范路径，拒绝 `..` 和越界链接目标。修改先返回前后正文与版本，提交再校验版本并通过暂存文件提交。SSH 命令执行权限允许该远端账号有权执行的命令，文件路径范围不构成 Shell 的权限限制。

所有 16 个内置插件均带 `automation` 说明。暂未开放执行能力的插件明确为 `tools: []`；这不妨碍其原有界面功能。当前没有开放本机任意命令、RDP/VNC/ADB/WDB 输入、配置同步修改或远程编辑器安装工具。

## AI 终端与任务结束

AI 建立独立 SSH PTY 后自动出现 **AI** 标签，不抢焦点。人工观察、AI 输入、手动接管使用同一个 PTY。命令按远端回显显示，不额外记录键盘输入，也不强制回显密码。

- 默认只读，允许选择、复制、翻阅；键盘、粘贴、中断和远端鼠标输入由前后端共同限制。
- 点击锁图标“解锁并人工接管”，取得唯一人工输入权；AI 后续输入和关联新动作暂停，已运行命令不会被自动 Ctrl+C。
- 点击“锁定并交还 AI”后恢复只读。控制代次变化，AI 必须重新读取状态；旧输入不会重放。其他页面只能观察，人工页面断线后控制权变为无人持有，需明确交还。
- 切换标签、最小化、不打开页面、刷新和关闭观察页面均不提前中断后台任务。刷新后附着原 PTY；后端重启不能恢复 Shell，也不会重放命令。
- AI 完成**整个工作**时调用 `task_finish`（成功、失败或取消），工作台收尾并自动关闭 SSH，不依赖用户观看或手动关闭。单次工具返回、Shell 提示符或暂时没有输出不会被误判为任务完成。AI 漏调收尾时由到期清理兜底，状态为中断。
- 若 AI 完成时用户正在接管，显示“AI 已结束，人工仍在使用”；交还或关闭后释放连接。只读观看不会阻止自动结束。
- 明确关闭 AI 终端或整组标签会结束关联任务。已结束标签只保留有界结果，不占活动连接名额；保留最近最多 8 个结果、30 分钟。历史库仍按原规则留存。

AI 终端复用分屏、悬浮和独立显示布局，保持来源标记。AI 控制时使用固定终端尺寸，观察者滚动查看，不因多个观察窗口反复调整远端行列；人工接管后由唯一控制页面调整尺寸。系统/文件侧栏暂不对 AI 观察终端开放，AI 经上述 MCP 工具调用这些能力。

后台使用 `@xterm/headless` 维护当前屏幕、模式和 2,000 行滚动历史。每个观察者独立同步画面并确认已解析字节；慢观察者会明确断开并可重新查看，后台任务继续。只有后端解析器回答终端设备查询。远端实时输出不会进入 Vue 状态或浏览器持久存储。

初始限制：每 AI 最多 2 个活动 SSH、全局最多 4 个 AI SSH，与终端/桌面/设备共同受 8 个连接预算约束；每终端最多 4 个观察者；每 AI 最多 4 个在途工具调用、全局 32 个。任务默认最长 30 分钟、可选 30 秒至 1 小时，10 分钟无操作则中断回收，人工持有也受期限约束。输出暂存最多 8 MiB 且最多 8,192 块，每次读取最多 64 KiB，并明确返回缺口。一般结果上限 512 KiB，操作记录最多 10,000 条并保留 7 天。以上不是容量压测结论。

## 插件接入契约

现有 `capabilities` 继续负责装配；新增可选 `automation`。声明结构与校验位于 [automation.ts](../shared/src/automation.ts)。省略声明或空工具列表合法，静态主题不允许声明执行工具。

每个工具声明 `id/version/title/description/inputSchema/outputSchema/access/scopes/execution/binding`。JSON Schema 顶层必须是对象，大小和深度有界，不支持外部引用。处理器通过 `api.registerAutomationTool(id, handler)` 显式注册，参数为 `(params, { clientId, signal })`。没有处理器或无法编译 schema 的工具不发布；返回值按 schema 验证，宿主封装为 `{ data, meta }`，metadata 标明实际提供者与版本。

通常使用 `binding: { kind: "plugin" }`，工具名为 `plugin.<插件 ID>.<工具 ID>`。绑定 service 的工具只能在该插件实际成为运行提供者时发布。声明标准 `contract` 时还必须匹配宿主标准 schema、权限与绑定；不匹配则使用独立名称，不能替换宿主工具。工具读取当前运行版本，安装中、待切换或缺少 handler 不会假装可用。连接器每五秒重新读取工具目录，SDK 发布变更通知；不支持动态工具更新的客户端需重新连接。

`access` 为 `write/execute` 时自动先准备再提交，`read` 可直接调用；`control` 用于有独立控制契约的操作。第三方处理器应检查 `signal` 并在取消时清理；不能将长期后台任务伪装为立即完成的请求。当前只发布第三方 `execution: request` 工具；`job` 声明可保留但不会发布。宿主内置后台任务协调仅支持 AI SSH 工作，通用插件后台 job API 留待后续扩展。插件调用持有自己的运行资源租约；AI SSH 持有 SSH、历史、文件与系统信息实际提供者的资源，结束后才能热切换。

插件本身仍拥有现有宿主进程权限；声明不是代码沙箱，也不会自动把全部 RPC、凭据服务或任意方法公开给 AI。

## 身份、操作记录与存储

MCP 协议由固定版本 `@modelcontextprotocol/server@2.4.0` 提供 stdio，内部 `/ws/automation` 只接受回环 Host、无浏览器 Origin/Cookie、独立 Ed25519 身份与双向签名挑战。签名绑定随机数、端口及双方公钥；服务公钥由可信工作台页面生成的配置固定。网页观察通道 `/ws/automation-terminal` 仍要求页面 Cookie、精确 Origin 和一次性观察票据；观察票据不授予输入权。

客户端、模板、最小任务与操作记录位于用户受限数据目录的 `automation.sqlite`，服务身份为 `automation-identity.pem`，各 AI 连接器的独立密钥保存在 `ai-clients/`。这些内容不进入目录导出、配置同步或普通日志。操作记录只保存 HMAC 摘要、状态及必要核对信息，不保存命令输入、文件正文或插件返回的任意结果。

准备操作先持久化记录，再返回签名票据。提交须同时存在原记录、有效票据、匹配的目标配置/凭据摘要、授权模板及运行插件；主机/用户名/端口、目标授权或提供者改变会使计划失效。重启时在途操作标为 `unknown`，过期或不存在的记录不会重新执行。远端写入与本机记录不是分布式事务，不承诺所有远端动作 exactly-once。已有历史可通过保存的任务元信息查询，实时屏幕和 Shell 不恢复。
