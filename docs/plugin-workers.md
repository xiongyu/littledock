# 插件 Worker 执行模型

WebNav 0.1.2 起，正式与开发入口的主线程不导入插件业务。任务管理器和系统优化分别声明独占 Worker，各持有一个专用线程；其他现有插件默认在共享 Worker 装配。所有插件从模块导入开始就在所属线程执行。静态主题不创建线程。

## 声明

省略执行声明即为共享，也可使用 `execution: { "backend": "shared" }`。独占示例：

```json
{
  "backend": "runtime/backend.js",
  "execution": { "backend": "dedicated" },
  "webnav": "^0.1.2"
}
```

拒绝 `host`、`worker` 等其他值、未知执行字段及无后端入口的声明；静态主题不创建线程。加载失败不会退回主线程。插件中心显示实际运行实例的位置，而不是仅显示安装清单。

共享插件相互影响：同步死循环阻塞同组插件、业务通信和会话处理，主线程入口、监测和停止控制仍可响应。独占插件不会直接占用共享线程，调用它的功能仍需等待。前端 Vue 仍在浏览器主线程；Worker 不是恶意代码沙箱，也不能防止进程级内存耗尽或原生模块崩溃。

## 框架职责

- `app-host.ts`：主线程回环 HTTP/WS 转发、Host 校验、连接限制、共享线程监测、退出和整包更新控制，不导入 `app.ts` 或插件实现。
- `app-worker.ts`：先建立框架消息通道，再动态导入 Cordis 应用及业务。默认组的对象和活动流由所属线程持有，保留 SSH、桌面和历史生命周期。
- `worker-host.ts` / `worker-entry.ts`：专用 Worker、消息接口、注册暂存、调用身份、取消、租约、订阅和清理；插件函数留在自己的线程。
- `service-host.ts` / `service-worker.ts`：内置服务的声明式执行器，按执行模式装配服务；协调端等待 `ready` 完成后才发布或切换服务。任务管理器引擎通过 `TaskManagerHost` 异步访问宿主，不导入宿主 Context。

共享线程的 Hono/ws 服务监听随机回环端口，仅接受主线程添加的随机内部凭据，并保留原公开 Host、Cookie 和精确 Origin 校验。内部凭据不交给浏览器、不写入公开配置或日志；直接访问内部端口被拒绝。仍使用原有业务 WS，没有新增 REST 接口。HTTP/WS 字节流通过 `pipe` 背压转发，主线程不缓存终端历史或解析桌面画面。

主入口最多 128 条连接。线程消息单条最多 2 MiB，每方向最多 64 个待完成请求、接收端最多 64 个活动调用，每秒最多 1,024 条消息；interop 另执行 256 KiB、调用深度及发布频率限制。独占 Worker 的 V8 老生代限额为 256 MiB，不包含全部原生或 Buffer 内存。原有业务会话及输出额度继续生效。

## SDK 与迁移

两种模式均提供异步宿主接口：

```ts
const status = await api.host.vaultStatus() // 只返回 unlocked
const release = await api.host.acquireResource()
try {
  // 获得租约后开始后台工作
} finally {
  release() // 幂等
}
```

当前 SDK 不再提供 `api.services`、同步 `api.acquireResource()` 或 `registerService(name, inject, factory)`，不保留兼容分支。服务直接注册实现对象，插件通过 `api.host` 和 `api.interop` 协作。维护或卸载期间，新的异步租约会被拒绝。RPC、连接器、自动化工具、interop 和清理仍由框架注册；跨线程调用的 owner 与 caller 由协调端保存的调用上下文关联，不相信插件填写的身份，取消信号单独传输。

任务管理器改为独立引擎与类型化异步宿主接口：采集、SSH、SFTP、进程动作、持续记录与历史处理在其 Worker；协调端保留鉴权、凭据出口、指纹原子核对和连接额度预留。开始监控先预留，资源实际释放后归还。异步授权与维护检查之后再次核对操作去重，避免等待造成重复写入。内置服务执行器按声明选择共享或独占，不在主线程执行插件代码。

系统优化 0.1.1 使用独占线程及异步宿主接口，后台任务和引擎保留租约，写入前核对解锁状态。模拟适配器仅存在于临时测试包。协作观察器、计数器和配色示例均默认共享。配色示例使用当前实现对象注册，数据保存在自己的 dataDirectory。使用新接口或声明的插件要求宿主 `^0.1.2`。

## 故障与生命周期

独占线程每秒报告存活，超过 10 秒无报告会被停止；退出或协议超限也撤销入口，未完成写入提示结果待核对。不自动重启或重放。异步等待不阻塞心跳；调用超时不等于工作完成，interop 租约在实际工作结束或线程退出后释放。

新版本在候选线程加载，验证成功且线程就绪后才发布；启动失败保留健康的旧实例。资源使用期间等待，可卸载后先清理再结束线程。外部独占插件清理最多等待 4 秒，超时提示失败并终止线程，不恢复旧注册。

共享线程超过 5 秒无状态报告，主线程标为无响应、断开转发通道，新的 HTTP 请求返回 503。线程恢复后可接回原后端持有会话；线程退出或明确重启后不能复活 Shell。不因单次超时自动重启共享线程。退出先请求整体清理，最多等待 10 秒后终止 Worker；正常退出显式等待插件及内置服务作用域的异步清理，再停止 Cordis，不能把 Cordis 的停止返回当作清理已完成。强制终止不保证外部副作用已撤销或任意第三方子进程已经退出，应核对未知结果；不按 PID 批量终止 mstsc、外部编辑器或独立持续记录器。

任务管理器清理最多等待 8 秒，正常收尾等待即时采集器和 SSH 退出；显式开启的目标持续记录器保持原生命周期。线程异常时保留尚未确认释放的额度，不用零计数掩盖未知资源。

整包更新必须收到实际收尾回复，无响应则报告阻塞，不把旧状态或空计数当作清理完成。托盘在状态不可用时显示未知。

## 验证

`backend/tests/plugin-workers.test.mjs` 使用真实入口、Worker、临时插件和本机模拟 SSH，覆盖线程位置、导入/处理器死循环、主线程响应、崩溃、跨线程身份与订阅、热更新回退、租约、消息额度、并发调用的独立取消、业务同名参数保留、关闭及终端指纹、字节流和原会话接回。任务管理器与持续记录回归已改为真实 Worker，并覆盖模拟 SSH/SFTP、本机隔离 HOME、指纹、并发写入去重、锁定和关闭释放。其他隔离服务测试仍通过内部 `app.ts` 装配 Context，不作为线程隔离证据；开发启动回归另覆盖实际启动脚本与隔离配置目录。

生产构建后，在仓库根目录运行 `node backend/tests/plugin-workers-built.mjs`，验证不带 TypeScript 加载器的共享及独占 Worker、鉴权 WS 和跨线程服务调用。

不连接真实远端、不改日常系统设置、不重启日常实例。实际执行批次见 README。
